# Правила использования MCP: GitLab

## Сценарии использования

Инструменты `GitLab` предназначены для управления репозиториями, CI/CD и рабочим процессом в GitLab.

## Типичные задачи

- **CI/CD (`list_pipelines`, `get_pipeline_summary`, `retry_job`):**
    - При сбоях в пайплайне, используй `get_pipeline_summary` для быстрой диагностики.
    - Анализируй логи упавших джобов (`get_job_log_smart`), чтобы понять причину.
    - Перезапускай упавшие джобы или пайплайны (`retry_job`, `retry_pipeline`), если это уместно.
- **Работа с Merge Requests (`create_merge_request`, `list_merge_requests`, `approve_merge_request`):**
    - Создавай MR для новых фич или багфиксов.
    - Просматривай изменения, коммиты и обсуждения в существующих MR.
- **Управление репозиторием (`list_branches`, `create_branch`, `get_file_contents`):**
    - Управляй ветками.
    - Читай файлы напрямую из репозитория.

## Алгоритм диагностики CI/CD

1.  **Получи ID пайплайна:** Если пользователь сообщает о проблеме со сборкой, найди нужный пайплайн с помощью `list_pipelines` (можно фильтровать по ветке `ref`).
2.  **Изучи общую картину:** Вызови `get_pipeline_summary` с ID пайплайна, чтобы увидеть, какие джобы на какой стадии упали.
3.  **Найди причину:** Для каждого упавшего джоба используй `get_job_log_smart` с флагом `error_only=true`, чтобы быстро извлечь строки с ошибками.
4.  **Предложи решение:** Основываясь на логах, предложи исправление в коде или конфигурации `.gitlab-ci.yml`.
