# План выполнения работ: Convertly Hub

Этот план составлен на основе технического задания и архитектурной документации.

## Незавершённые задачи — приоритетный обзор

Этот раздел дублирует все незакрытые пункты из тематических разделов ниже, чтобы следующий этап работы был виден сразу. Канонические чекбоксы остаются в исходных разделах; после выполнения обновляются оба места.

Обозначения: `+` — задачу можно выполнять уже сейчас; `-` — пока не берём в работу. Цифра — общий приоритет, где `1` самый высокий.

1. **(-, 10) Платежи и тарифы — заморожено до выбора провайдера**
   - **Почему не завершено:** тарифы и `PaymentModal` пока являются демонстрационным UI; не выбран провайдер и поэтому отсутствуют checkout, проверка webhook, идемпотентная синхронизация подписки и управление доступом.
   - **Как выполнить:** после выбора провайдера определить модель подписок и страны/валюты, реализовать checkout, customer portal, верификацию и идемпотентную обработку webhook, затем связать тариф с правами пользователя и добавить контрактные тесты.
   - **Когда:** намеренно отложено; не входит в ближайший локальный MVP и возобновляется только после продуктового решения о провайдере.

2. **(-, 9) Backend‑5 — `PDF → DOCX`**
   - **Почему не завершено:** PDF обычно не содержит полной структуры исходного документа, а Gotenberg не даёт качественную обратную конвертацию; текущий Core поддерживает только `JPG ↔ PNG` и `DOCX → PDF`.
   - **Как выполнить:** выбрать специализированный best-effort движок, подготовить эталонные PDF/DOCX и критерии приемлемой потери форматирования, добавить очередь/таймауты и отдельные quality-тесты.
   - **Когда:** после подтверждения бизнес-ценности направления и выбора движка; не блокирует текущий MVP.

3. **(-, 8) Backend‑8 — общий rate limiter для нескольких инстансов**
   - **Почему не завершено:** текущий лимит 30 запросов в минуту на API-ключ хранится в памяти одного процесса; при нескольких экземплярах приложения лимиты будут независимыми.
   - **Как выполнить:** подключить Redis-совместимое хранилище, применить атомарный sliding/fixed-window алгоритм, добавить health-check, метрики и интеграционные тесты конкурирующих запросов.
   - **Когда:** до горизонтального масштабирования или production-развёртывания с несколькими репликами Next.js.

4. **(-, 7) Backend‑9 — производительность поиска админ-панели на большой БД**
   - **Почему не завершено:** cursor-pagination уже исключает большой `OFFSET`, но поиск подстрокой по имени/email через `contains` не имеет специализированного PostgreSQL-индекса.
   - **Как выполнить:** снять `EXPLAIN (ANALYZE, BUFFERS)` на реалистичных данных, при необходимости добавить миграцию с `pg_trgm` и GIN-индексами, затем сравнить план и время ответа.
   - **Когда:** при росте таблицы пользователей или перед production-нагрузкой; не требуется для текущего MVP-объёма данных.

5. **(+, 6) Прочие задачи‑2 — реальные backend integration/E2E тесты**
   - **Почему не завершено:** 84 unit-, component- и route-теста покрывают серверную логику с изоляцией зависимостей, а UI E2E-сценарии существуют; но нет полноценного E2E-набора, который через HTTP использует реальную PostgreSQL, MinIO и Gotenberg для auth, API-ключей, конвертации и admin API.
   - **Как выполнить:** выделить изолированную тестовую БД/бакет, seed-пользователей и ключей, расширить Playwright/API tests критическими сценариями и очищать данные после запуска.
   - **Когда:** перед staging/production и после подключения Dashboard к реальным backend-контрактам.

6. **(-, 11) Прочие задачи‑3 — production deployment**
   - **Почему не завершено:** локальный Docker Compose проверен, но нет целевой платформы, production-конфигурации, CI/CD и эксплуатационной процедуры.
   - **Как выполнить:** сравнить Vercel, Render и Oracle Cloud Free Tier по региону, стоимости, лимитам, managed PostgreSQL/S3/Redis и возможности постоянно запускать Gotenberg. Vercel удобен для Next.js, но Gotenberg и постоянное файловое хранилище нужно вынести во внешние сервисы; Render позволяет развернуть web и worker-сервисы, но бесплатные лимиты и сон сервисов непригодны для стабильной обработки; Oracle Free Tier может вместить Docker Compose на VM, но требует самостоятельного администрирования, backup и проверки доступности выбранного региона. После выбора: настроить секреты, миграции, HTTPS/домен, backup/restore, мониторинг, CI/CD и runbook.
   - **Когда:** после закрытия обязательных production-пунктов выше и до первого публичного релиза.

Подтверждение Telegram брать из уже реализованной webhook-привязки.
   - **Готово, когда:** пароль сбрасывается по одноразовой ссылке без раскрытия существования email, а UI показывает реальные статусы.
