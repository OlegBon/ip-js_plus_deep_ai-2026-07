## Backend

1.  **Аутентификация пользователей:** (выполнено)
    - [x] Настроить `NextAuth.js` для управления JWT-сессиями через HttpOnly cookies и защитить маршруты личного кабинета.
2.  **Логика регистрации/входа:** (выполнено)
    - [x] Реализовать хэширование паролей (`bcrypt`), регистрацию, проверку учётных данных и вход через Credentials Provider.
3.  **Роли пользователей и Telegram:** (выполнено)
    - [x] Реализовать серверную RBAC-проверку: `USER` и `ADMIN` имеют доступ к Dashboard, а `/management` — только `ADMIN`.
    - [x] Добавить безопасный процесс назначения первого администратора и аудита последующих изменений роли.
    - [x] Реализовать привязку Telegram через одноразовый токен, верификацию webhook и подтверждение `telegramId` в профиле.
4.  **API для конвертации (`POST /api/v1/convert`):** (выполнено)
    - [x] Создать основной маршрут для приёма `multipart/form-data` запросов.
    - [x] Реализовать аутентификацию по Bearer токену (API-ключ).
    - [x] Валидировать поддерживаемые MIME-типы, целевой формат и размер файла до 10 МБ; создавать задачу `PENDING` и возвращать `202 Accepted`.
5.  **Ядро конвертации (Core):** (выполнено для текущего MVP)
    - [x] Интегрировать библиотеку `sharp` для быстрой обработки изображений (JPG ↔ PNG).
    - [x] Реализовать логику делегирования конвертации документов (DOCX → PDF) воркеру `Gotenberg`.
    - [x] Добавить асинхронный жизненный цикл задания `PENDING → PROCESSING → COMPLETED/FAILED`, проверку сигнатуры исходного файла и безопасное фиксирование метаданных результата.
    - [ ] `PDF → DOCX` остаётся planned: потребуется специализированный best-effort-движок, эталонные тестовые документы и предупреждение о возможной потере форматирования.
6.  **Управление приватностью:** Написать логику, которая в зависимости от настроек пользователя либо сохраняет файл в S3, либо отдает его потоком.
7.  **Генерация API-ключей:** Разработать механизм создания, хэширования и отзыва API-ключей.
8.  **Безопасность и валидация:**
    - Реализовать ограничение частоты запросов (Rate Limiting) для API.
    - Добавить серверную валидацию размера (`Payload Too Large`) и типа (`MIME-type`) файлов.
    - Обеспечить корректную обработку ошибок от воркеров (например, `422 Unprocessable Entity`).
9.  **Логика для Админ-панели:** Создать API-эндпоинты для поиска, блокировки пользователей и отзыва ключей.
