# План E2E-тестування

## Автоматизовано зараз

- Головна сторінка: гість бачить дві обмежені зони конвертації та CTA реєстрації; авторизований користувач — тарифні напрями через сесію.
- Вхід: форма Credentials і редирект до особистого кабінету.
- Тарифи: неавторизований вибір платного тарифу спрямовує на реєстрацію з вибраним планом. Mock Checkout авторизованого користувача покрито component/route-тестами до появи ізольованого backend E2E-середовища.
- Dashboard і Admin: component/UI-сценарії з реальними account/admin API-контрактами, ізольованими моками мережі.
- Реальний backend integration/E2E: окремий Docker Compose-стек із PostgreSQL,
  MinIO, Gotenberg і MailHog перевіряє `GET /api/health`, реєстрацію та
  Credentials-сесію, API-ключі, збережену й потокову API-конвертацію,
  guest image-квоту, `DOCX → PDF` і admin user-management API. Запуск:
  `npm run test:integration`.

## Залишається розширити

- Відновлення пароля, верифікація email і Telegram: видача, строк дії та одноразовість токенів.
- Browser-конвертація авторизованого користувача: окремі реальні сценарії `JPG ↔ PNG`, `DOCX → PDF`, session-download і зберігання з браузера.
- Гостьова конвертація: document-квота, 1 МБ, IP limiter, відсутність S3/історії та тимчасове повторне завантаження в поточній вкладці.
- Публічний `POST /api/v1/convert`: негативні сценарії Bearer-автентифікації та rate limiting.
- Налаштування профілю, email verification, password reset, Telegram linking, API-ключі та історія конвертацій із постійним зберіганням у PostgreSQL/S3.
- Реальний checkout і обробка webhook від платіжного провайдера.

Розширення, що потребують інфраструктури, мають і надалі використовувати
ізольовану тестову БД, S3-емулятор і Gotenberg у Docker Compose; зовнішні
HTTP-інтеграції мають мокуватися через MSW.
