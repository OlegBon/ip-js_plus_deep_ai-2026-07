# План E2E-тестирования

## Автоматизировано сейчас

- Главная страница: гость видит две ограниченные зоны конвертации и CTA регистрации; авторизованный пользователь — тарифные направления через сессию.
- Вход: форма Credentials и редирект в личный кабинет.
- Тарифы: неавторизованный выбор платного тарифа направляет на регистрацию с выбранным планом. Mock Checkout авторизованного пользователя покрыт component/route-тестами до появления изолированной backend E2E-среды.
- Dashboard и Admin: component/UI-сценарии с реальными account/admin API-контрактами, изолированными моками сети.
- Реальный backend integration/E2E: отдельный Docker Compose-стек с PostgreSQL,
  MinIO, Gotenberg и MailHog проверяет `GET /api/health`, регистрацию и
  Credentials-сессию, API-ключи, сохранённую и потоковую API-конвертацию,
  guest image-квоту, `DOCX → PDF` и admin user-management API. Запуск:
  `npm run test:integration`.

## Остаётся расширить

- Восстановление пароля, верификация email и Telegram: выдача, срок действия и одноразовость токенов.
- Browser-конвертация авторизованного пользователя: отдельные реальные сценарии `JPG ↔ PNG`, `DOCX → PDF`, session-download и хранения из браузера.
- Гостевая конвертация: document-квота, 1 МБ, IP limiter, отсутствие S3/истории и временное повторное скачивание в текущей вкладке.
- Публичный `POST /api/v1/convert`: негативные сценарии Bearer-аутентификации и rate limiting.
- Настройки профиля, email verification, password reset, Telegram linking, API-ключи и история конвертаций с постоянным хранением в PostgreSQL/S3.
- Реальный checkout и обработка webhook от платёжного провайдера.

Расширения, которые требуют инфраструктуры, должны продолжать использовать
изолированную тестовую БД, S3-эмулятор и Gotenberg в Docker Compose; внешние
HTTP-интеграции должны мокироваться через MSW.
