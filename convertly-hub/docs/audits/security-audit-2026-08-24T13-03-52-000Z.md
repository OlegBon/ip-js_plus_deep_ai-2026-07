# Аудит безопасности Convertly Hub

- **UTC-метка:** 2026-08-24T13:03:52.000Z
- **Область:** API админ-панели, RBAC, Prisma-запросы и управление API-ключами.

## 1. Аудит зависимостей

`npm audit --omit=dev` сообщает о 3 уязвимостях уровня **high** в транзитивной цепочке `prisma` → `@prisma/config` → `deepmerge-ts` (GHSA-ggr8-5vv4-36mx). Автоматический `npm audit fix --force` требует breaking-изменения Prisma и не применялся.

## 2. Поиск секретов

Поиск по отслеживаемому коду не выявил production API-ключей, приватных ключей или AWS access key. Значения `.env` не читались и не включались в отчёт.

## 3. Анализ Prisma Schema

Схема не менялась. `User.password` остаётся обязательной строкой без значения по умолчанию для bcrypt-хеша; `ApiKey.keyHash` остаётся уникальным хешем. Индексы `User.status` и `ApiKey(userId, revokedAt)` соответствуют существующим сценариям фильтрации и управления ключами. Поиск подстрокой `contains` по имени/email не имеет специализированного индекса: для большой таблицы после проверки `EXPLAIN` потребуется отдельный `pg_trgm` индекс.

## 4. Анализ API-маршрутов

- Все `/api/admin/*` маршруты требуют сессию и перед операцией сверяют актуальные `role=ADMIN` и `status=ACTIVE` через ограниченный Prisma `select`; устаревший JWT сам по себе права не даёт.
- Выдача пользователей использует cursor-pagination, лимит 1–50 и не возвращает пароль, токены, хеши или API-секреты.
- Смена статуса принимает только `ACTIVE`/`SUSPENDED`, а собственный статус администратора запрещён. Отзыв API-ключа выполняется атомарным `updateMany` только для ещё активного ключа; история конвертаций остаётся.
- Raw SQL, конкатенация пользовательского ввода и сетевые вызовы внутри транзакций отсутствуют. API-аудит подтвердил доступность приложения, PostgreSQL, Gotenberg и MinIO в локальной среде.
