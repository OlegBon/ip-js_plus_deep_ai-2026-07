# Аудит безопасности Convertly Hub

- **UTC-метка:** 2026-08-24T09:00:40.894Z
- **Область:** NextAuth.js, сессии, Prisma-схема и API-маршруты.

## 1. Аудит зависимостей

`npm audit --omit=dev` обнаружил 3 уязвимости высокого уровня в транзитивной зависимости `deepmerge-ts`, поступающей через Prisma CLI. Автоматическое исправление предлагает несовместимое изменение Prisma, поэтому оно не применялось.

## 2. Поиск секретов

Секреты не захардкожены в новом auth-коде. NextAuth читает существующую приватную переменную `NEXTAUTH_SECRET`; она не имеет префикса `NEXT_PUBLIC_`. Учётные данные инфраструктуры по-прежнему находятся только в корневом `.env`.

## 3. Prisma Schema

Схема не менялась. Поле `User.password` остаётся обязательным полем для хеша без значения по умолчанию. JWT-сессии не требуют таблиц NextAuth и не дублируют чувствительные данные в базе.

## 4. API-маршруты

Добавлен только стандартный обработчик NextAuth.js. Сессия хранится как зашифрованный JWT в cookie с `HttpOnly`, `SameSite=Lax`, `Path=/` и `Secure` в production. Серверный layout проверяет сессию до рендера защищённых маршрутов. Вход по паролю намеренно не подключён до отдельной задачи с `bcrypt` и валидацией учётных данных.

## Рекомендации

- Перед production заменить `NEXTAUTH_SECRET` на уникальное значение из защищённого хранилища секретов.
- Не ослаблять параметры cookie и не передавать секреты через `NEXT_PUBLIC_*`.
- При обновлении Prisma повторить `npm audit` и выбрать совместимое исправление зависимости.
