# Аудит безпеки Convertly Hub

- **UTC-мітка:** 2026-08-24T09:00:40.894Z
- **Область:** NextAuth.js, сесії, Prisma-схема та API-маршрути.

## 1. Аудит залежностей

`npm audit --omit=dev` виявив 3 вразливості високого рівня у транзитивній залежності `deepmerge-ts`, що надходить через Prisma CLI. Автоматичне виправлення пропонує несумісну зміну Prisma, тому його не застосовували.

## 2. Пошук секретів

Секрети не захардкоджені у новому auth-коді. NextAuth читає наявну приватну змінну `NEXTAUTH_SECRET`; вона не має префікса `NEXT_PUBLIC_`. Облікові дані інфраструктури, як і раніше, містяться лише у кореневому `.env`.

## 3. Prisma Schema

Схема не змінювалася. Поле `User.password` залишається обов'язковим полем для хешу без значення за замовчуванням. JWT-сесії не потребують таблиць NextAuth і не дублюють чутливі дані в базі.

## 4. API-маршрути

Додано лише стандартний обробник NextAuth.js. Сесія зберігається як зашифрований JWT у cookie з `HttpOnly`, `SameSite=Lax`, `Path=/` і `Secure` у production. Серверний layout перевіряє сесію до рендерингу захищених маршрутів. Вхід за паролем навмисно не підключено до окремої задачі з `bcrypt` і валідацією облікових даних.

## Рекомендації

- Перед production замінити `NEXTAUTH_SECRET` на унікальне значення із захищеного сховища секретів.
- Не послаблювати параметри cookie та не передавати секрети через `NEXT_PUBLIC_*`.
- За оновлення Prisma повторити `npm audit` і обрати сумісне виправлення залежності.
