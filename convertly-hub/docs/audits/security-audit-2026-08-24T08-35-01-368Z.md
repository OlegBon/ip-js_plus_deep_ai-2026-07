# Аудит безпеки Convertly Hub

- **UTC-мітка:** 2026-08-24T08:35:01.368Z
- **Область:** зберігання секретів, конфігурація Docker, Prisma та API-маршрути.

## 1. Аудит залежностей

`npm audit --omit=dev` виявив 3 вразливості високого рівня у транзитивній залежності `deepmerge-ts`, що надходить через Prisma CLI. Автоматичне виправлення пропонує несумісне за версією зниження Prisma, тому його не застосовували. Перед оновленням слід дочекатися сумісної версії Prisma з виправленою залежністю або окремо спланувати міграцію.

## 2. Пошук секретів

**Виправлено.** Облікові дані PostgreSQL і MinIO було задано у `docker-compose.yml`. Compose тепер отримує їх лише з кореневого `.env` через змінні `POSTGRES_*`, `MINIO_ACCESS_KEY` і `MINIO_SECRET_KEY`.

Перевірка вихідного коду та конфігурацій не виявила інших секретів поза `.env`. Файл `.env` виключено з Git правилами `.gitignore`.

## 3. Prisma Schema

`prisma/schema.prisma` використовує `DATABASE_URL` з оточення. Поле пароля користувача обов'язкове, рядкового типу та не має значення за замовчуванням. У схемі передбачено зберігання API-ключів і одноразових токенів у вигляді хешів.

## 4. API-маршрути

Єдиний поточний маршрут `app/api/health/route.ts` створює підключення з `DATABASE_URL`; рядок підключення не захардкоджено. Вхідні дані маршрут не приймає. Для майбутніх API-маршрутів залишаються обов'язковими перевірка авторизації та валідація вхідних даних.

## Рекомендації

- Перед staging/production замінити локальні облікові дані та `NEXTAUTH_SECRET` на унікальні значення із захищеного сховища секретів.
- Не додавати приватні змінні з префіксом `NEXT_PUBLIC_`.
- За наступного оновлення Prisma повторно виконати `npm audit`.
