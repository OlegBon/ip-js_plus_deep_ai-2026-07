# Отчёт аудита безопасности — 2026-08-24T12:01:47.252Z

## Проверки

- Проведён аудит API: приложение, PostgreSQL, Gotenberg и MinIO доступны в локальном окружении.
- Для `POST /api/v1/convert` проверены два режима приватности: при `storeConversions=true` файл сохраняется только в приватном user-scoped S3-ключе; при `false` S3 не вызывается, а ответ имеет `Cache-Control: no-store`.
- `GET /api/v1/conversions/:conversionId/download` требует Bearer API-ключ, ограничивает запрос `userId` владельца и возвращает `404` для чужого или отсутствующего результата без раскрытия его существования.
- Публичные и presigned S3 URL не формируются. Внешние вызовы S3 и Core выполняются вне Prisma-транзакций.
- Поиск отслеживаемого кода не выявил захардкоженных production-секретов. Совпадения `DATABASE_URL` находятся только в учебных примерах `.agents/skills` и не являются конфигурацией приложения.

## Зависимости

`npm audit --omit=dev` обнаружил 3 уязвимости уровня **high** в транзитивной цепочке `prisma` → `@prisma/config` → `deepmerge-ts` (GHSA-ggr8-5vv4-36mx). Доступное автоматическое исправление требует `npm audit fix --force` и понижает Prisma до 6.12.0, то есть является breaking-изменением. Оно не применялось в рамках этой задачи.

## Итог

Реализованный privacy-поток не публикует файлы и не раскрывает чужие результаты. Перед обновлением Prisma требуется отдельная проверка совместимости и план миграции.
