# Аудит безопасности Convertly Hub

- **UTC-метка:** 2026-08-24T12:24:50.044Z
- **Область:** жизненный цикл API-ключей, Prisma и session-защищённые API-маршруты.

## 1. Аудит зависимостей

`npm audit --omit=dev` сообщает о 3 уязвимостях уровня **high** в транзитивной цепочке `prisma` → `@prisma/config` → `deepmerge-ts` (GHSA-ggr8-5vv4-36mx). Предложенный `npm audit fix --force` требует breaking-изменения Prisma, поэтому в этой задаче не применялся.

## 2. Поиск секретов

Поиск по отслеживаемому коду не выявил типичных production API-ключей, приватных ключей или AWS access key. Значения `.env` не читались и не включались в отчёт.

## 3. Анализ Prisma Schema

`User.password` — обязательная строка без значения по умолчанию и предназначена для bcrypt-хеша. `ApiKey.keyHash` — обязательное уникальное поле; исходный API-секрет в схеме не хранится. Индекс `(userId, revokedAt)` соответствует выдаче и owner-scoped отзыву активных ключей. Изменение схемы не требуется.

## 4. Анализ API-маршрутов

- `GET`/`POST /api/account/api-keys` и `DELETE /api/account/api-keys/:apiKeyId` требуют NextAuth-сессию и дополнительно проверяют, что пользователь существует и имеет статус `ACTIVE`.
- Секрет генерируется через `crypto.randomBytes`, хешируется SHA-256 и возвращается только в `201 Created`; список никогда не возвращает хеш или секрет. Успешный ответ создания имеет `Cache-Control: no-store`.
- Отзыв использует `updateMany` с условиями `id`, `userId` и `revokedAt: null`, поэтому не может затронуть чужой либо уже отозванный ключ. Raw SQL и сетевые вызовы внутри транзакций отсутствуют.
- Рекомендация: перед production отдельно спланировать совместимое обновление Prisma для устранения уязвимости зависимости и добавить rate limiting для маршрута создания ключей в следующей security-задаче.
