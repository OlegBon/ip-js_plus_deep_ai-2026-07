# Аудит безпеки Convertly Hub

- **UTC-мітка:** 2026-08-24T12:24:50.044Z
- **Область:** життєвий цикл API-ключів, Prisma та session-захищені API-маршрути.

## 1. Аудит залежностей

`npm audit --omit=dev` повідомляє про 3 вразливості рівня **high** у транзитивному ланцюжку `prisma` → `@prisma/config` → `deepmerge-ts` (GHSA-ggr8-5vv4-36mx). Запропонований `npm audit fix --force` потребує breaking-зміни Prisma, тому у цій задачі не застосовувався.

## 2. Пошук секретів

Пошук за відстежуваним кодом не виявив типових production API-ключів, приватних ключів або AWS access key. Значення `.env` не читалися й не включалися до звіту.

## 3. Аналіз Prisma Schema

`User.password` — обов'язковий рядок без значення за замовчуванням і призначений для bcrypt-хешу. `ApiKey.keyHash` — обов'язкове унікальне поле; вихідний API-секрет у схемі не зберігається. Індекс `(userId, revokedAt)` відповідає видачі та owner-scoped відкликанню активних ключів. Зміна схеми не потрібна.

## 4. Аналіз API-маршрутів

- `GET`/`POST /api/account/api-keys` і `DELETE /api/account/api-keys/:apiKeyId` потребують NextAuth-сесію та додатково перевіряють, що користувач існує й має статус `ACTIVE`.
- Секрет генерується через `crypto.randomBytes`, хешується SHA-256 і повертається лише у `201 Created`; список ніколи не повертає хеш або секрет. Успішна відповідь створення має `Cache-Control: no-store`.
- Відкликання використовує `updateMany` з умовами `id`, `userId` і `revokedAt: null`, тому не може зачепити чужий або вже відкликаний ключ. Raw SQL і мережеві виклики всередині транзакцій відсутні.
- Рекомендація: перед production окремо спланувати сумісне оновлення Prisma для усунення вразливості залежності та додати rate limiting для маршруту створення ключів у наступній security-задачі.
