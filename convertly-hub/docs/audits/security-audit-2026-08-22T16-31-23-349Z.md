# Звіт аудиту безпеки — 2026-08-22T16:31:23.349Z

## Короткий підсумок

Проведено базовий аудит залежностей, потенційно жорстко заданих секретів, Prisma-схеми та реалізованих API-маршрутів. Критичних проблем не виявлено. Потребують планового виправлення три вразливості залежностей рівня `high` і кілька конфігураційних ризиків, які не можна переносити до спільного або production-оточення.

## Аудит залежностей

- **Статус:** `npm audit` виявив 3 вразливості рівня `high`.
- **Джерело:** транзитивна залежність `deepmerge-ts` через `@prisma/config` і пакет `prisma`.
- **Ризик:** рекурсивні графи об'єктів можуть призвести до вичерпання стека під час злиття об'єктів.
- **Дія:** не запускати автоматично `npm audit fix --force`: запропонована npm зміна є breaking change. Дібрати сумісне оновлення Prisma та повторити `npm audit` окремою задачею.

## Секрети та конфігурація

- **Позитивний результат:** значення з `.env` не потрапили до вихідного коду; S3-сервіс читає ключі лише із серверних змінних оточення.
- **Високий ризик для спільних оточень:** у `docker-compose.yml` задано стандартні облікові дані PostgreSQL і MinIO. Для локальної розробки це допустимо лише за обмеженого доступу до комп'ютера; для staging і production значення мають передаватися із захищеного оточення та не зберігатися в репозиторії.
- **Середній ризик:** Docker Compose публікує порти PostgreSQL, MinIO і Gotenberg на всі інтерфейси хоста. У спільній мережі або production потрібно обмежити їх loopback-інтерфейсом, приватною Docker-мережею або firewall.
- **Середній ризик:** `next.config.ts` не задає HTTP security headers. До публікації застосунку потрібні щонайменше CSP, `X-Content-Type-Options`, `X-Frame-Options` або `frame-ancestors`, `Referrer-Policy` і HSTS для HTTPS-оточень.

## Prisma-схема

- Поле `User.password` має тип `String`, обов'язкове та без значення за замовчуванням.
- API-ключі та одноразові токени передбачено як унікальні хеші (`keyHash`, `*TokenHash`); відкриті значення не описані схемою.
- Тимчасові поля використовують `timestamptz(3)`, а зв'язки та зовнішні ключі міграцій визначено явно.

## API-маршрути

- Реалізовано лише `GET /api/health`; він використовує Prisma без raw SQL, а клієнту повертає загальне повідомлення за помилки.
- **Низький ризик:** публічна відповідь містить кількість користувачів і статуси внутрішніх сервісів. Перед production обмежте доступ до health-маршруту або залиште в ньому лише агрегований статус.
- Маршрути аутентифікації, конвертації та керування файлами ще не реалізовано; під час їх створення обов'язкові серверна валідація, авторизація та rate limiting.

## Пріоритети

1. Окремо виправити вразливість `deepmerge-ts` сумісним оновленням залежностей.
2. Винести Docker-облікові дані з versioned Compose-конфігурації для спільних оточень і обмежити опубліковані порти.
3. Додати security headers і переглянути публічний контракт `/api/health` до production.
