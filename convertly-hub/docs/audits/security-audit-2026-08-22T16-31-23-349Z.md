# Отчёт аудита безопасности — 2026-08-22T16:31:23.349Z

## Краткий итог

Проведён базовый аудит зависимостей, потенциально жёстко заданных секретов, Prisma-схемы и реализованных API-маршрутов. Критических проблем не выявлено. Требуют планового исправления три уязвимости зависимостей уровня `high` и несколько конфигурационных рисков, которые нельзя переносить в общее или production-окружение.

## Аудит зависимостей

- **Статус:** `npm audit` выявил 3 уязвимости уровня `high`.
- **Источник:** транзитивная зависимость `deepmerge-ts` через `@prisma/config` и пакет `prisma`.
- **Риск:** рекурсивные объектные графы могут привести к исчерпанию стека при слиянии объектов.
- **Действие:** не запускать автоматически `npm audit fix --force`: предложенное npm изменение является breaking change. Подобрать совместимое обновление Prisma и повторить `npm audit` отдельной задачей.

## Секреты и конфигурация

- **Положительный результат:** значения из `.env` не попали в исходный код; S3-сервис читает ключи только из серверных переменных окружения.
- **Высокий риск для общих окружений:** в `docker-compose.yml` заданы стандартные учётные данные PostgreSQL и MinIO. Для локальной разработки это допустимо только при ограниченном доступе к компьютеру; для staging и production значения должны передаваться из защищённого окружения и не храниться в репозитории.
- **Средний риск:** Docker Compose публикует порты PostgreSQL, MinIO и Gotenberg на все интерфейсы хоста. В общей сети или production необходимо ограничить их loopback-интерфейсом, приватной Docker-сетью или firewall.
- **Средний риск:** `next.config.ts` не задаёт HTTP security headers. До публикации приложения нужны как минимум CSP, `X-Content-Type-Options`, `X-Frame-Options` или `frame-ancestors`, `Referrer-Policy` и HSTS для HTTPS-окружений.

## Prisma-схема

- Поле `User.password` имеет тип `String`, обязательное и без значения по умолчанию.
- API-ключи и одноразовые токены предусмотрены как уникальные хеши (`keyHash`, `*TokenHash`); открытые значения не описаны схемой.
- Временные поля используют `timestamptz(3)`, а связи и внешние ключи миграций определены явно.

## API-маршруты

- Реализован только `GET /api/health`; он использует Prisma без raw SQL, а клиенту возвращает общее сообщение при ошибке.
- **Низкий риск:** публичный ответ содержит число пользователей и статусы внутренних сервисов. Перед production ограничьте доступ к health-маршруту или оставьте в нём только агрегированный статус.
- Маршруты аутентификации, конвертации и управления файлами ещё не реализованы; при их создании обязательны серверная валидация, авторизация и rate limiting.

## Приоритеты

1. Отдельно исправить уязвимость `deepmerge-ts` совместимым обновлением зависимостей.
2. Вынести Docker-учётные данные из versioned Compose-конфигурации для общих окружений и ограничить опубликованные порты.
3. Добавить security headers и пересмотреть публичный контракт `/api/health` до production.
