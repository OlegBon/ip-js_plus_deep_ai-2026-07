# Аудит безпеки Convertly Hub

- **UTC-мітка:** 2026-09-11T10:36:38.951Z
- **Область:** production dependency tree, відстежуваний код, Prisma schema та API-маршрути.

## Підсумок

Виявлено **4 dependency vulnerabilities**: 1 critical, 1 high і 2 moderate. У коді не знайдено production-секретів; базові auth, validation і Prisma-перевірки присутні.

## 2. Пошук секретів

Пошук відстежуваного коду (без `.env`, Markdown, lockfile і `node_modules`) не виявив production OpenAI, GitHub, AWS або приватних ключів. Збіги із token/secret значеннями є лише контрольованими test fixtures у `lib/**/__tests__` та `app/api/health/__tests__`; вони не є реальними credentials. Значення змінних середовища не читалися й не включалися до звіту.

## 3. Аналіз Prisma Schema

`User.password` — обов’язковий `String` без default. Password reset, email verification, Telegram linking і API keys зберігають лише унікальні hash-поля (`*TokenHash`, `keyHash`), а не первинні секрети. User-owned залежності мають FK-зв’язки з `Cascade`/`SetNull` відповідно до життєвого циклу даних. Зауважень до типів чутливих полів не виявлено.

## 4. Аналіз API-маршрутів

- Account routes перевіряють серверну сесію й active user; admin routes додатково звіряють актуальні `ADMIN`/`ACTIVE` права через domain service, а не покладаються лише на JWT.
- API conversion routes вимагають Bearer API key, plan entitlement, rate limit, multipart content type, `File`/`targetFormat` і core validation; некоректні input мають контрольовані `400`/`413`/`415`/`422` відповіді.
- Параметри адмін-списків і зміни статусу проходять через спеціалізовані parse-функції. Єдиний знайдений raw SQL — статичний tagged Prisma-запит `SELECT 1` у health check; `queryRawUnsafe`/`executeRawUnsafe` не знайдено.
- `/api/health` повертає лише агреговані `up`/`down` стани залежностей без конфігурації чи текстів внутрішніх помилок.

## Наступні дії

1. Пріоритетно випустити вузьке оновлення `next` і `sharp` у окремій гілці з повним regression-набором.
2. Окремо спланувати сумісне оновлення `next-auth`/`nodemailer`, оскільки запропонований `npm audit fix --force` є breaking.
3. Після оновлень повторити `npm audit --omit=dev`, cloud API-аудит і smoke-test conversion/email flows.
