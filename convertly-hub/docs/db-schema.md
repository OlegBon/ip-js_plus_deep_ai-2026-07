# Схема базы данных

Документ описывает Prisma-схему Convertly Hub для PostgreSQL. В репозитории есть миграции `20260824093000_rbac_telegram` для RBAC/Telegram, `20260825090000_subscription_quotas` для тарифов и квот и `20260826120000_quota_reservations` для атомарного резервирования места в хранилище. В новом окружении перед использованием Telegram, тарифов или конвертации примените все миграции командой `npx prisma migrate deploy`.

## Перечисления

| Перечисление | Значения | Назначение |
| --- | --- | --- |
| `UserRole` | `USER`, `ADMIN` | Доступ к пользовательским и административным действиям. |
| `UserStatus` | `ACTIVE`, `SUSPENDED` | Блокировка учётной записи без её удаления. |
| `SubscriptionPlan` | `FREE`, `BASIC`, `PRO`, `ENTERPRISE` | Активный либо ожидающий тариф. |
| `SubscriptionStatus` | `ACTIVE`, `PENDING_DEMO` | Активная подписка либо единственная ожидающая demo-заявка. |
| `ConversionStatus` | `PENDING`, `PROCESSING`, `COMPLETED`, `FAILED` | Состояние обработки файла. |

## Модели

### `User`

Пользователь, его настройки, состояние доступа и связи с ключами/конвертациями.

| Поле | Тип | Ограничения и назначение |
| --- | --- | --- |
| `id` | `String` | Первичный ключ, UUID. |
| `email` | `String` | Обязательное уникальное значение; остаётся действующим до подтверждения замены. |
| `pendingEmail` | `String?` | Необязательное уникальное новое значение email до подтверждения одноразовой ссылкой. |
| `password` | `String` | Обязательный хеш пароля; открытый пароль не хранится. |
| `role` | `UserRole` | Обязательное, по умолчанию `USER`. |
| `status` | `UserStatus` | Обязательное, по умолчанию `ACTIVE`; индекс для административной фильтрации. |
| `plan` | `SubscriptionPlan` | Обязательное, по умолчанию `FREE`. |
| `storeConversions` | `Boolean` | Обязательная настройка хранения результатов, по умолчанию `true`. |
| auth и Telegram-поля | `String?` / `DateTime?` | Хеши одноразовых токенов, сроки действия и даты подтверждения; `emailVerificationExpires` и `passwordResetExpires` дают email-ссылкам TTL 30 минут, хеши и Telegram ID уникальны. |
| `apiKeys`, `conversions` | связи | Один пользователь имеет много API-ключей и записей конвертаций. |
| `subscription` | связь `Subscription?` | One-to-one подписка; старые записи до миграции используют `plan` пользователя как fallback. |

### `Subscription`

`id` — первичный UUID; `userId` — обязательный уникальный внешний ключ на `User` с каскадным удалением. `activePlan` обязателен и имеет default `FREE`; `requestedPlan` необязателен и хранит последнюю смену; `status`, `createdAt` и `updatedAt` обязательны. Mock Checkout не сохраняет поля формы или платёжные данные.

### `ApiKey`

Ключ публичного API. Секрет ключа хранится только в виде `keyHash`; `keyPrefix` предназначен для безопасного отображения в UI.

| Поле | Тип | Ограничения и назначение |
| --- | --- | --- |
| `id` | `String` | Первичный ключ, UUID. |
| `name` | `String` | Обязательное имя ключа, по умолчанию `Default`. |
| `keyHash` | `String` | Обязательное уникальное SHA-256-значение для аутентификации; исходный секрет в БД не хранится. |
| `keyPrefix` | `String` | Несекретный префикс ключа для отображения. |
| `lastUsedAt`, `revokedAt` | `DateTime?` | Время последнего использования и отзыва ключа. |
| `userId` | `String` | Обязательный внешний ключ на `User`; при удалении пользователя ключ удаляется каскадно. |
| `conversions` | связь | Конвертации, инициированные этим ключом. |

Индекс `@@index([userId, revokedAt])` поддерживает выдачу активных ключей пользователя.

### `RoleChangeAudit`

Неизменяемая запись о назначении первого администратора и последующих изменениях ролей. `actorUserId` пуст только у однократного bootstrap-назначения, а `targetUserId`, старая и новая роли записываются всегда. Индексы поддерживают аудит по целевому пользователю и инициатору.

### `ConversionLog`

Метаданные одной конвертации. В БД не хранятся бинарные файлы: `storageKey` связывает сохранённый результат с S3-совместимым хранилищем.

| Поле | Тип | Ограничения и назначение |
| --- | --- | --- |
| `id` | `String` | Первичный ключ, UUID. |
| `sourceFileName`, `sourceMimeType`, `sourceSize` | `String`, `String`, `BigInt` | Обязательные метаданные исходного файла. |
| `targetFormat` | `String` | Обязательный целевой формат. |
| `status` | `ConversionStatus` | Обязательное состояние, по умолчанию `PENDING`. |
| result-поля | `String?` / `BigInt?` | Метаданные результата после успешной обработки. |
| `storageReservationBytes` | `BigInt?` | Короткое серверное резервирование размера результата во время `PROCESSING`; снимается при успешной записи в S3 или ошибке. |
| `storageKey` | `String?` | Уникальный ключ объекта в S3; `null` для режима без хранения. |
| `errorMessage` | `String?` | Контекст ошибки конвертации без чувствительных данных. |
| lifecycle-поля | `DateTime?` | Время старта, завершения и истечения временной ссылки. |
| `userId` | `String` | Обязательный внешний ключ на `User`; каскадное удаление записей при удалении пользователя. |
| `apiKeyId` | `String?` | Необязательный внешний ключ на `ApiKey`; при удалении ключа ссылка становится `null`. |

Индексы `@@index([userId, createdAt])`, `@@index([userId, expiresAt])`, `@@index([status, createdAt])` и `@@index([apiKeyId])` поддерживают историю пользователя, расчёт storage, обработку очереди и аудит API-вызовов.

Usage Dashboard считает успешные конвертации текущего месяца и сумму `resultSize` неистёкших либо бессрочных строк с `storageKey`; обход S3 для каждого запроса не нужен. Перед S3-upload сервер под PostgreSQL advisory lock резервирует `storageReservationBytes`, поэтому параллельные воркеры не могут превысить общий storage-лимит. `expiresAt` фиксируется при завершении по активному на тот момент тарифу.

## Время и применение миграций

Все временные поля хранятся в PostgreSQL как `timestamptz(3)`. Одноразовые токены подтверждения и сброса пароля должны сравниваться по хешу: исходное значение допускается показать или отправить пользователю лишь в момент создания.

Секрет API-ключа создаётся криптографически стойким генератором и возвращается только в момент создания; интерфейсы списка и отзыва используют лишь метаданные. Для нового окружения применяйте отслеживаемые миграции командой `npx prisma migrate deploy`. При изменении `prisma/schema.prisma` создавайте отдельную миграцию в локальной разработке, проверяйте её на данных, близких к production, и только затем применяйте к общим окружениям.
