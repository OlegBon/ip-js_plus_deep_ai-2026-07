# Database Migrations

Безопасно изменяйте структуру данных в Convertly Hub: PostgreSQL и Prisma 7.

## Перед изменением

1. Прочитайте `prisma/schema.prisma`, относящиеся миграции и код, работающий с изменяемыми моделями.
2. Определите, меняется ли схема, данные, индекс или поведение удаления. Оцените объём таблицы, блокировки и план отката.
3. Не меняйте миграцию, которая могла быть применена в общем окружении: создайте новую.

## Безопасные паттерны

- Новое поле в существующей таблице добавляйте nullable или с безопасным default; `NOT NULL` вводите после backfill и проверки данных.
- Разделяйте DDL и массовое изменение данных. Backfill выполняйте порциями; не удерживайте длинную транзакцию.
- Для rename/remove используйте expand-contract: совместимая схема, затем совместимый код приложения, затем удаление старого поля.
- При добавлении relation проверяйте внешний ключ, `onDelete`, уникальность и индекс для реальных сценариев `JOIN` и фильтрации.
- Для больших таблиц отдельно планируйте индексы и блокировки. `CREATE INDEX CONCURRENTLY` не работает в транзакционном блоке.

## Команды и проверка

- До применения форматируйте схему и проверяйте сгенерированный diff миграции.
- `prisma migrate dev`, `prisma migrate deploy`, `prisma db push`, `prisma migrate reset` и изменяющий SQL запускайте лишь после явного разрешения пользователя.
- `migrate reset` допустим только для одноразовой локальной базы разработки.
- После разрешённого применения проверьте статус миграций, генерацию Prisma Client и сценарии доступа к изменённым моделям.
- Обновите `docs/db-schema.md`, а при изменении потоков данных — `docs/architecture.md` и `docs/progress.md`.

Не раскрывайте `DATABASE_URL` и другие секреты.
