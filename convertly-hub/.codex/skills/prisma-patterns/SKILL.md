# Prisma Patterns

Используйте Prisma 7 как типобезопасный слой доступа к PostgreSQL, не теряя контроль над SQL-семантикой и производительностью.

## Контекст

- Проект использует PostgreSQL, Prisma 7, `@prisma/adapter-pg` и `prisma-client-js`.
- Каноническая схема — `prisma/schema.prisma`; миграции — `prisma/migrations/`.
- Prisma Client в Next.js должен безопасно переиспользоваться, а не создавать новый пул на каждый запрос.

## Схема и Prisma Client

- Моделируйте связи relation-полями, `@unique`, `@@index` и `onDelete` по фактическим сценариям доступа.
- При добавлении relation учитывайте индекс внешнего ключа и миграцию существующих данных.
- В чтении используйте `select` или ограниченный `include`, особенно в списках и вложенных relation.
- Для зависимых операций используйте `$transaction`; callback транзакции должен быть коротким и не выполнять внешний HTTP-вызов.
- Для конкурирующих обновлений предпочитайте атомарные операции (`increment`, `decrement`, `upsert`) либо транзакцию вместо read-modify-write в приложении.
- Raw SQL используйте только когда Prisma Client недостаточен; применяйте параметризацию и документируйте причину.

## Маршрутизация

Для изменения схемы и миграции используйте `database-migrations`; для анализа SQL и индексов — `postgres-patterns`.

## Результат

Опишите модели и методы Prisma Client, выбор `select`/`include`, транзакции, необходимость миграции и оставшиеся риски производительности.
