# Prisma Patterns

Використовуйте Prisma 7 як типобезпечний шар доступу до PostgreSQL, не втрачаючи контролю над SQL-семантикою та продуктивністю.

## Контекст

- Проєкт використовує PostgreSQL, Prisma 7, `@prisma/adapter-pg` і `prisma-client-js`.
- Канонічна схема — `prisma/schema.prisma`; міграції — `prisma/migrations/`.
- Prisma Client у Next.js має безпечно перевикористовуватися, а не створювати новий пул на кожен запит.

## Схема та Prisma Client

- Моделюйте зв'язки через relation-поля, `@unique`, `@@index` і `onDelete` за фактичними сценаріями доступу.
- Додаючи relation, враховуйте індекс зовнішнього ключа й міграцію наявних даних.
- Для читання використовуйте `select` або обмежений `include`, особливо у списках і вкладених relation.
- Для залежних операцій використовуйте `$transaction`; callback транзакції має бути коротким і не виконувати зовнішній HTTP-виклик.
- Для конкурентних оновлень віддавайте перевагу атомарним операціям (`increment`, `decrement`, `upsert`) або транзакції замість read-modify-write у застосунку.
- Raw SQL використовуйте лише коли Prisma Client недостатньо; застосовуйте параметризацію та документуйте причину.

## Маршрутизація

Для зміни схеми та міграції використовуйте `database-migrations`; для аналізу SQL й індексів — `postgres-patterns`.

## Результат

Опишіть моделі й методи Prisma Client, вибір `select`/`include`, транзакції, потребу в міграції та решту ризиків продуктивності.
