# PostgreSQL Patterns

Применяйте PostgreSQL-паттерны к фактическому запросу, объёму данных и требованиям к согласованности.

## Схема и запросы

- Выбирайте типы по смыслу: `text` для строк без оправданного лимита, `numeric` или минимальные целые единицы для денег, согласованные временные метки.
- Явно моделируйте первичные, внешние и уникальные ключи, обязательность полей и поведение удаления связей.
- Внешний ключ не создаёт индекс автоматически: добавляйте его, когда поле участвует в `JOIN`, фильтре или удалении родительской записи.
- В production-коде выбирайте только нужные поля, избегая неограниченного `SELECT *`.
- В составном индексе сначала размещайте поля точного равенства, затем диапазона или сортировки. Частичный индекс используйте, когда предикат стабильно совпадает с запросом.
- Для больших списков предпочитайте cursor/keyset-пагинацию большому `OFFSET`; ищите N+1 и устраняйте его пакетной загрузкой.

## Конкурентность, безопасность и диагностика

- Держите транзакции короткими; не выполняйте сетевые вызовы, удерживая блокировки.
- Для связанных блокировок используйте единый порядок захвата. `FOR UPDATE SKIP LOCKED` подходит только после проверки требований очереди.
- Для критичных запросов предложите `EXPLAIN (ANALYZE, BUFFERS)` на репрезентативной базе. Не запускайте анализ, исполняющий запрос, без разрешения пользователя.
- Используйте Prisma Client или параметризованный SQL; не конкатенируйте пользовательский ввод.
- RLS и разграничение доступа рассматривайте при появлении multi-tenant или публичного доступа, а не формально.
