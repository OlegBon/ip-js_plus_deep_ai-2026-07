# Мета навички

Провести серію автоматизованих і напівавтоматизованих перевірок для виявлення поширених уразливостей у коді проєкту.

# Умови активації

Активуй, якщо користувач просить: «перевір безпеку», «зроби аудит безпеки», «знайди уразливості».

# Інструкції з виконання

Дій суворо за кроками, використовуючи інструменти аналізу коду.

## Крок 1: Перевірка залежностей

Використай `run_shell_command` для запуску `npm audit`. Це допоможе виявити уразливості у використаних бібліотеках.

- **Команда:** `npm audit`
- **Що шукати:** Наявність уразливостей (vulnerabilities). Якщо їх знайдено, повідом кількість і рівень критичності.

## Крок 2: Пошук жорстко закодованих секретів

Використай `grep_search` для пошуку потенційних API-ключів, паролів або інших секретів, залишених у коді.

- **Патерн пошуку:** `(sk-proj-|password|secret|token|key)[=:]\s*['"]`
- **Що шукати:** Будь-які збіги, які схожі на облікові дані. Виключи з пошуку файли `.md` і `package-lock.json`.

## Крок 3: Аналіз Prisma Schema

Прочитай `prisma/schema.prisma` і перевір базові аспекти безпеки.

- **Файл:** `prisma/schema.prisma`
- **Що шукати:**
    1. Переконайся, що поле `password` у моделі `User` має тип `String` і не має значень за замовчуванням.
    2. Перевір, що для чутливих даних не використовуються непризначені для цього типи.

## Крок 4: Аналіз API-маршрутів

Перевір наявні API-маршрути щодо базової валідації.

- **Директорія:** `app/api/`
- **Що шукати:**
    1. Чи є валідація вхідних даних (наприклад, через `zod` або ручні перевірки)?
    2. Чи використовуються параметризовані запити до бази даних (Prisma Client робить це за замовчуванням)?

## Крок 5: Збереження звіту

Після перевірок сформуй Markdown-звіт із висновками, серйозністю, ризиками та рекомендованими діями. На початку аудиту зафіксуй одну UTC-мітку часу у ISO 8601.

Збережи ідентичний вміст у двох файлах:

- `docs/audits/security-audit-latest.md` — перезаписуваний актуальний звіт;
- `docs/audits/security-audit-<UTC-мітка>.md` — незмінний історичний звіт, де в імені `:` і `.` замінено на `-`.

Наприклад, мітці `2026-08-22T16:31:23.349Z` відповідає файл `security-audit-2026-08-22T16-31-23-349Z.md`. Не видаляй і не перейменовуй попередні датовані звіти. Не включай до звіту значення секретів, рядки підключення або вміст `.env`.

# Формат відповіді

Сформуй звіт у форматі Markdown, підсумовуючи результати кожного кроку:

1.  **Аудит залежностей:** (результат `npm audit`)
2.  **Пошук секретів:** (збіги знайдено або не знайдено)
3.  **Аналіз Prisma Schema:** (зауваження щодо схеми)
4.  **Аналіз API-маршрутів:** (зауваження щодо коду API)

Укажи шляхи до обох збережених звітів і заверши відповідь суворо фразою: _"Аудит безпеки завершено. Звіти сформовано. Чекаю на подальші вказівки."_
