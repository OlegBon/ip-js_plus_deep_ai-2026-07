# Правила використання MCP: Chrome DevTools

## Загальний принцип

Ти маєш прямий доступ до запущеного браузера Chrome для налагодження frontend. Не проси користувача «подивитися, що в консолі» або «скопіювати помилку». З'ясовуй це сам.

## Умови виклику

Ти **зобов'язаний** використовувати `Chrome DevTools` у таких випадках:

1.  **Візуальні баги:** користувач повідомляє про проблеми з версткою («кнопка з'їхала», «елементи накладаються один на одного», «модальне вікно не відкривається»).
2.  **Помилки в Runtime:** на frontend виникає помилка (білий екран, клік не працює, застосунок «завис»).
3.  **Проблеми з мережею:** виникають помилки під час взаємодії з backend (помилки CORS, `4xx Bad Request`, `5xx Internal Server Error`).

## Алгоритм налагодження

1.  **Зроби знімок сторінки (`take_snapshot`):** почни з отримання актуального стану DOM і accessibility tree. Це твоє основне джерело інформації про елементи на сторінці.
2.  **Перевір консоль (`list_console_messages`):** проаналізуй повідомлення в консолі, особливо помилки (`error`, `warn`), щоб знайти JavaScript-винятки та їхні стектрейси.
3.  **Вивчи мережу (`list_network_requests`):** якщо проблема пов'язана з API, перевір список мережевих запитів. Зверни увагу на:
    - статус-код відповіді;
    - тіло запиту (`request body`);
    - тіло відповіді (`response body`).
4.  **Проаналізуй стилі (через `evaluate_script`):** якщо проблема у верстці, ти можеш використати `evaluate_script` для отримання обчислених стилів елемента (`window.getComputedStyle(element)`), щоб зрозуміти, які CSS-правила застосувалися і чи немає конфліктів.
5.  **Сформулюй рішення:** на основі зібраних даних запропонуй точний фікс у коді (React-компонент, стилі Tailwind CSS тощо).
