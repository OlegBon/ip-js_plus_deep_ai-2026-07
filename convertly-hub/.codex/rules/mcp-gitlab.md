# Правила використання MCP: GitLab

## Сценарії використання

Інструменти `GitLab` призначені для керування репозиторіями, CI/CD і робочим процесом у GitLab.

## Типові завдання

- **CI/CD (`list_pipelines`, `get_pipeline_summary`, `retry_job`):**
    - За збоїв у пайплайні використовуй `get_pipeline_summary` для швидкої діагностики.
    - Аналізуй логи джобів, що впали (`get_job_log_smart`), щоб зрозуміти причину.
    - Перезапускай джоби або пайплайни, що впали (`retry_job`, `retry_pipeline`), якщо це доречно.
- **Робота з Merge Requests (`create_merge_request`, `list_merge_requests`, `approve_merge_request`):**
    - Створюй MR для нових фіч або багфіксів.
    - Переглядай зміни, коміти й обговорення в наявних MR.
- **Керування репозиторієм (`list_branches`, `create_branch`, `get_file_contents`):**
    - Керуй гілками.
    - Читай файли безпосередньо з репозиторію.

## Алгоритм діагностики CI/CD

1.  **Отримай ID пайплайна:** якщо користувач повідомляє про проблему зі збіркою, знайди потрібний пайплайн за допомогою `list_pipelines` (можна фільтрувати за гілкою `ref`).
2.  **Вивчи загальну картину:** виклич `get_pipeline_summary` з ID пайплайна, щоб побачити, які джоби на якій стадії впали.
3.  **Знайди причину:** для кожного джоба, що впав, використай `get_job_log_smart` із прапорцем `error_only=true`, щоб швидко витягти рядки з помилками.
4.  **Запропонуй рішення:** спираючись на логи, запропонуй виправлення в коді або конфігурації `.gitlab-ci.yml`.
