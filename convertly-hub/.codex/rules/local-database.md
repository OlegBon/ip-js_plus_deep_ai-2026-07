# Локальні правила: база даних

Застосовуйте ці правила під час зміни Prisma-схеми, міграцій, SQL або server-side доступу до PostgreSQL.

1. Прочитайте `database-migrations` для змін схеми й міграцій, `prisma-patterns` для Prisma Client та `postgres-patterns` для SQL, індексів і продуктивності.
2. Не запускайте команди, що змінюють БД, без явного дозволу користувача; `prisma migrate reset` не використовуйте поза одноразовою локальною базою розробки.
3. Не розкривайте рядки підключення та інші секрети.
4. За зміни схеми оновлюйте `docs/db-schema.md`, за зміни потоків даних — `docs/architecture.md`, а результати перевірок фіксуйте в `docs/progress.md`.
