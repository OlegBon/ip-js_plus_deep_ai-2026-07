# Локальные правила: React Хуки

> Этот файл содержит правила по использованию хуков React (`useState`, `useEffect`, `useMemo`, `useCallback` и кастомных хуков).

## 1. Правила хуков

Всегда соблюдайте "Правила хуков", проверяемые `eslint-plugin-react-hooks`:

1.  **Вызывайте хуки только на верхнем уровне** функции-компонента или другого хука.
2.  **Никогда не вызывайте хуки** внутри циклов, условий, вложенных функций или после `return`.
3.  **Хуки должны вызываться в одном и том же порядке** при каждом рендере.

## 2. `useEffect`: когда НЕ использовать

`useEffect` предназначен для **синхронизации с внешними системами** (подписки, API браузера, сторонние библиотеки).

**Не используйте** `useEffect` для:

-   **Производного состояния:** вычисляйте его во время рендера.
-   **Трансформации данных для рендера:** делайте это во время рендера.
-   **Сброса состояния при изменении пропсов:** используйте `key` на компоненте.
-   **Уведомления родителя об изменении:** вызывайте колбэк в обработчике события.

```tsx
// НЕПРАВИЛЬНО: эффект для производного состояния
const [fullName, setFullName] = useState("");
useEffect(() => {
  setFullName(`${first} ${last}`);
}, [first, last]);

// ПРАВИЛЬНО: вычислять во время рендера
const fullName = `${first} ${last}`;
```

## 3. Массивы зависимостей

-   **Всегда включайте все реактивные значения**, используемые внутри эффекта/колбэка.
-   Включите правило `react-hooks/exhaustive-deps` и никогда не отключайте его без комментария.
-   Если функция передается в зависимости, оберните ее в `useCallback` только если она сама является зависимостью другого хука или передается в мемоизированный дочерний компонент.

## 4. Очистка (`cleanup`)

Каждая подписка, интервал, слушатель событий или сетевой запрос должен иметь функцию очистки.

```tsx
useEffect(() => {
  const controller = new AbortController();
  fetch(url, { signal: controller.signal });
  return () => controller.abort(); // Отмена запроса при размонтировании
}, [url]);
```

Отсутствие очистки приводит к утечкам памяти и гонкам состояний.

## 5. `useMemo` и `useCallback`: когда это оправдано

По умолчанию, **не мемоизируйте**. Добавляйте `useMemo` / `useCallback` только когда:

1.  Значение передается в дочерний компонент, обернутый в `React.memo`.
2.  Значение является зависимостью другого хука (`useEffect`, `useMemo`).
3.  Вычисление является **измеримо дорогим** (проверяйте профилировщиком).

Преждевременная мемоизация усложняет код и может быть медленнее, чем повторное вычисление.

## 6. Кастомные хуки

Выносите логику в кастомный хук, когда:

-   Одна и та же последовательность хуков (`useState` + `useEffect`) повторяется в 2+ компонентах.
-   Логика имеет четкое, именуемое предназначение (`useDebounce`, `useLocalStorage`).
-   Вы хотите тестировать эту логику независимо от компонентов.

## 7. Паттерны `useState`

-   **Функциональное обновление**, когда новое состояние зависит от предыдущего: `setCount(c => c + 1)`.
-   Группируйте связанное состояние в один объект только если они всегда меняются вместе. В противном случае, разделяйте на несколько вызовов `useState`.
-   Используйте `useReducer`, когда логика переходов между состояниями усложняется.
