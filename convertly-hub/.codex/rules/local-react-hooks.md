# Локальні правила: хуки React

> Цей файл містить правила використання хуків React (`useState`, `useEffect`, `useMemo`, `useCallback` і кастомних хуків).

## 1. Правила хуків

Завжди дотримуйся «Правил хуків», які перевіряє `eslint-plugin-react-hooks`:

1.  **Викликай хуки лише на верхньому рівні** функції-компонента або іншого хука.
2.  **Ніколи не викликай хуки** всередині циклів, умов, вкладених функцій або після `return`.
3.  **Хуки мають викликатися в одному й тому самому порядку** під час кожного рендеру.

## 2. `useEffect`: коли НЕ використовувати

`useEffect` призначений для **синхронізації із зовнішніми системами** (підписки, API браузера, сторонні бібліотеки).

**Не використовуй** `useEffect` для:

-   **Похідного стану:** обчислюй його під час рендеру.
-   **Перетворення даних для рендеру:** роби це під час рендеру.
-   **Скидання стану за зміни пропсів:** використовуй `key` на компоненті.
-   **Сповіщення батьківського компонента про зміну:** викликай колбек в обробнику події.

```tsx
// НЕПРАВИЛЬНО: ефект для похідного стану
const [fullName, setFullName] = useState("");
useEffect(() => {
  setFullName(`${first} ${last}`);
}, [first, last]);

// ПРАВИЛЬНО: обчислювати під час рендеру
const fullName = `${first} ${last}`;
```

## 3. Масиви залежностей

-   **Завжди додавай усі реактивні значення**, використані всередині ефекту або колбека.
-   Увімкни правило `react-hooks/exhaustive-deps` і ніколи не вимикай його без коментаря.
-   Якщо функцію передають у залежності, обгорни її в `useCallback` лише коли вона сама є залежністю іншого хука або передається до мемоізованого дочірнього компонента.

## 4. Очищення (`cleanup`)

Кожна підписка, інтервал, слухач подій або мережевий запит має мати функцію очищення.

```tsx
useEffect(() => {
  const controller = new AbortController();
  fetch(url, { signal: controller.signal });
  return () => controller.abort(); // Скасування запиту під час демонтування
}, [url]);
```

Відсутність очищення призводить до витоків пам'яті та перегонів станів.

## 5. `useMemo` і `useCallback`: коли це виправдано

За замовчуванням **не мемоізуй**. Додавай `useMemo` / `useCallback` лише коли:

1.  Значення передається дочірньому компоненту, обгорнутому в `React.memo`.
2.  Значення є залежністю іншого хука (`useEffect`, `useMemo`).
3.  Обчислення є **вимірно дорогим** (перевіряй профайлером).

Передчасна мемоізація ускладнює код і може бути повільнішою за повторне обчислення.

## 6. Кастомні хуки

Винось логіку в кастомний хук, коли:

-   та сама послідовність хуків (`useState` + `useEffect`) повторюється у 2+ компонентах;
-   логіка має чітке, іменоване призначення (`useDebounce`, `useLocalStorage`);
-   ти хочеш тестувати цю логіку незалежно від компонентів.

## 7. Патерни `useState`

-   **Функціональне оновлення**, коли новий стан залежить від попереднього: `setCount(c => c + 1)`.
-   Групуй пов'язаний стан в один об'єкт лише якщо його частини завжди змінюються разом. В іншому разі розділяй на кілька викликів `useState`.
-   Використовуй `useReducer`, коли логіка переходів між станами ускладнюється.
