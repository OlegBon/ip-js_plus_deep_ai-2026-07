# Правила использования MCP: Chrome DevTools

## Общий принцип

Ты имеешь прямой доступ к запущенному браузеру Chrome для отладки фронтенда. Не проси пользователя "посмотреть, что в консоли" или "скопировать ошибку". Выясняй это сам.

## Триггеры для вызова

Ты **обязан** использовать `Chrome DevTools` в следующих случаях:

1.  **Визуальные баги:** Пользователь сообщает о проблемах с версткой ("кнопка съехала", "элементы накладываются друг на друга", "модальное окно не открывается").
2.  **Ошибки в Runtime:** На фронтенде возникает ошибка (белый экран, неработающий клик, приложение "зависло").
3.  **Проблемы с сетью:** Возникают ошибки при взаимодействии с бэкендом (ошибки CORS, `4xx Bad Request`, `5xx Internal Server Error`).

## Алгоритм отладки

1.  **Сделай снимок страницы (`take_snapshot`):** Начни с получения актуального состояния DOM и accessibility tree. Это твой основной источник информации об элементах на странице.
2.  **Проверь консоль (`list_console_messages`):** Проанализируй сообщения в консоли, особенно ошибки (`error`, `warn`), чтобы найти JavaScript-исключения и их стектрейсы.
3.  **Изучи сеть (`list_network_requests`):** Если проблема связана с API, проверь список сетевых запросов. Обрати внимание на:
    - Статус-код ответа.
    - Тело запроса (`request body`).
    - Тело ответа (`response body`).
4.  **Проанализируй стили (через `evaluate_script`):** Если проблема в верстке, ты можешь использовать `evaluate_script` для получения вычисленных стилей элемента (`window.getComputedStyle(element)`), чтобы понять, какие CSS-правила применились и нет ли конфликтов.
5.  **Сформулируй решение:** На основе собранных данных предложи точный фикс в коде (React-компонент, стили Tailwind CSS и т.д.).
