# Локальные правила: Стиль кода и Данные

> Этот файл расширяет общие правила по стилю кодирования, добавляя специфичные для React соглашения.

## 1. Расширения файлов

- `.tsx` для любого файла, содержащего JSX.
- `.ts` для чистой логики, кастомных хуков без JSX и утилит.
- `.test.tsx` / `.test.ts` для тестов, отражая имя исходного файла.

## 2. Именование

- **Компоненты:** `PascalCase` для символа и для файла (`UserCard.tsx` -> `export function UserCard...`).
- **Кастомные хуки:** `useCamelCase` для символа (`useDebounce`).
- **Контекст:** `<Domain>Context` для символа, `<Domain>Provider` для компонента-провайдера, `use<Domain>` для хука-потребителя.
- **Обработчики событий:** `handleClick`, `handleSubmit` внутри компонента; проп, который его получает, называется `onClick`, `onSubmit`.
- **Булевы пропсы:** `isLoading`, `hasError`, `canSubmit` — никогда не используйте `loading` или `error` в качестве булевых значений.

## 3. Структура компонента

```tsx
type Props = {
  user: User;
  onSelect: (id: string) => void;
};

export function UserCard({ user, onSelect }: Props) {
  // ...
}
```

- Используйте `type Props = {}` для описания пропсов компонента.
- Всегда деструктурируйте пропсы в списке параметров.
- Не указывайте тип возвращаемого значения для JSX (`function Foo(): JSX.Element`), TypeScript выведет его автоматически.

## 4. JSX

- Используйте самозакрывающиеся теги, если нет дочерних элементов: `<img />`.
- Используйте фрагменты `<>...</>` вместо оборачивающих `<div>`, если дополнительный DOM-узел не нужен.
- **Условный рендеринг:**
    - `{condition && <Foo />}` для булевых условий.
    - Тернарный оператор для выбора одного из двух вариантов.
    - `return null;` (ранний выход) для защитных проверок.
- Не встраивайте сложную многострочную логику в JSX. Выносите ее в константы над `return`.

## 5. Граница "Сервер-Клиент" (Next.js App Router)

- По умолчанию все компоненты являются **Серверными**.
- Добавляйте директиву `"use client"` на первой строке файла, только если компонент использует состояние (`useState`), эффекты (`useEffect`), ссылки (`useRef`), браузерные API или обработчики событий.
- Никогда не импортируйте файл с `"use client"` из файла с `"use server"`.

## 6. Проектирование данных (КРИТИЧНО)

- При описании схем баз данных, DDL-скриптов или ORM-моделей **запрещено** использовать общие слова вроде «ограничения» (constraints).
- Ты **обязан** явно и точно прописывать:
    - **Primary Keys** (первичные ключи).
    - **Mandatory fields** (обязательные поля, `NOT NULL`).
    - **Unique indexes** (уникальные индексы).
    - **Foreign keys** (внешние ключи и связи между таблицами).
