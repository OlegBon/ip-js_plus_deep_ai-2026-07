# Локальні правила: стиль коду та дані

> Цей файл розширює загальні правила стилю кодування, додаючи домовленості, специфічні для React.

## 1. Розширення файлів

- `.tsx` для будь-якого файлу, що містить JSX.
- `.ts` для чистої логіки, кастомних хуків без JSX і утиліт.
- `.test.tsx` / `.test.ts` для тестів із назвою, що відображає ім'я вихідного файлу.

## 2. Найменування

- **Компоненти:** `PascalCase` для символу та файлу (`UserCard.tsx` -> `export function UserCard...`).
- **Кастомні хуки:** `useCamelCase` для символу (`useDebounce`).
- **Контекст:** `<Domain>Context` для символу, `<Domain>Provider` для компонента-провайдера, `use<Domain>` для хука-споживача.
- **Обробники подій:** `handleClick`, `handleSubmit` усередині компонента; пропс, який його отримує, називається `onClick`, `onSubmit`.
- **Булеві пропси:** `isLoading`, `hasError`, `canSubmit` — ніколи не використовуй `loading` або `error` як булеві значення.

## 3. Структура компонента

```tsx
type Props = {
  user: User;
  onSelect: (id: string) => void;
};

export function UserCard({ user, onSelect }: Props) {
  // ...
}
```

- Використовуй `type Props = {}` для опису пропсів компонента.
- Завжди деструктуруй пропси у списку параметрів.
- Не вказуй тип значення, що повертається для JSX (`function Foo(): JSX.Element`), TypeScript виведе його автоматично.

## 4. JSX

- Використовуй самозакривні теги, якщо немає дочірніх елементів: `<img />`.
- Використовуй фрагменти `<>...</>` замість обгортальних `<div>`, якщо додатковий DOM-вузол не потрібен.
- **Умовний рендеринг:**
    - `{condition && <Foo />}` для булевих умов;
    - тернарний оператор для вибору одного з двох варіантів;
    - `return null;` (ранній вихід) для захисних перевірок.
- Не вбудовуй складну багаторядкову логіку в JSX. Винось її в константи над `return`.

## 5. Межа «сервер—клієнт» (Next.js App Router)

- За замовчуванням усі компоненти є **серверними**.
- Додавай директиву `"use client"` у першому рядку файлу, лише якщо компонент використовує стан (`useState`), ефекти (`useEffect`), посилання (`useRef`), браузерні API або обробники подій.
- Ніколи не імпортуй файл із `"use client"` з файлу з `"use server"`.

## 6. Проєктування даних (КРИТИЧНО)

- Під час опису схем баз даних, DDL-скриптів або ORM-моделей **заборонено** використовувати загальні слова на кшталт «обмеження» (constraints).
- Ти **зобов'язаний** чітко й точно зазначати:
    - **Primary Keys** (первинні ключі);
    - **Mandatory fields** (обов'язкові поля, `NOT NULL`);
    - **Unique indexes** (унікальні індекси);
    - **Foreign keys** (зовнішні ключі та зв'язки між таблицями).
