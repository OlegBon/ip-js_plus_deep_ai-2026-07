# Локальные правила: Тестирование

> Этот файл содержит правила по тестированию React-приложений.

## 1. Инструменты

-   **Тест-раннер:** Vitest или Jest.
-   **Тестирование компонентов:** **React Testing Library (RTL)** — стандарт для проекта.
-   **E2E тесты:** Playwright.
-   **Мокирование API:** MSW (Mock Service Worker).

## 2. Основной принцип

**Тестируй то, что видит и делает пользователь, а не детали реализации.**

-   **Никогда не тестируй:**
    -   Внутреннее состояние компонента.
    -   Пропсы, переданные дочерним компонентам.
    -   Какие хуки были вызваны.
-   **Ищи элементы в таком порядке:**
    1.  По роли, доступной пользователю (`getByRole`, `getByLabelText`).
    2.  По тексту (`getByText`).
    3.  В крайнем случае, по `data-testid`.

## 3. Взаимодействие с пользователем

-   Используй **`userEvent`** вместо `fireEvent`. `userEvent` симулирует реальное поведение пользователя в браузере (клики, ввод текста с клавиатуры), в то время как `fireEvent` просто вызывает одно событие.
-   Всегда используй `await` при вызовах `userEvent`.

```tsx
import userEvent from "@testing-library/user-event";

test("форма должна отправляться корректно", async () => {
  const user = userEvent.setup();
  render(<MyForm onSubmit={handleSubmit} />);

  await user.type(screen.getByLabelText("Email"), "user@example.com");
  await user.click(screen.getByRole("button", { name: /отправить/i }));

  expect(handleSubmit).toHaveBeenCalledWith({ email: "user@example.com" });
});
```

## 4. Асинхронные операции

-   Для поиска элементов, которые появляются асинхронно, используй `findBy*` (например, `await screen.findByText("Загружено")`).
-   Для ожидания выполнения побочных эффектов (например, вызова функции) используй `waitFor`.

## 5. Мокирование API

-   Используй **MSW (Mock Service Worker)** для всех тестов, которые делают сетевые запросы. Это позволяет тестировать компонент, хуки и библиотеку для `fetch` в условиях, приближенных к реальным.

## 6. Snapshot-тесты

-   **Избегай Snapshot-тестов для компонентов.** Они хрупкие, их сложно рецензировать, и они часто одобряются без должного внимания.
-   Используй их только для чистого вывода данных (например, сериализация объекта в строку).
-   Для визуальной регрессии используй скриншот-тесты в Playwright.

## 7. Тестирование кастомных хуков

-   Используй `renderHook` из RTL.
-   Оборачивай вызовы, изменяющие состояние, в `act`.

```tsx
import { renderHook, act } from "@testing-library/react";

test("хук useCounter должен инкрементировать значение", () => {
  const { result } = renderHook(() => useCounter());
  act(() => {
    result.current.increment();
  });
  expect(result.current.count).toBe(1);
});
```
