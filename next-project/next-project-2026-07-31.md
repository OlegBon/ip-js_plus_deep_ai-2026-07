# Мета навички (Skill Objective)

Виявлення потенційних проблем на боці сервера у відповідях API з фінансовими даними. Навичка гарантує, що дані відповідають очікуваним структурам frontend до того, як потраплять до бізнес-логіки, і формує звіт для backend-розробників, щоб усунути неточності.

# Тригери активації (Triggers)

Активуй цю навичку, якщо запит користувача містить:

- «Перевір відповіді API» / «Проведи аудит фінансових ендпоїнтів»
- «Перевір дані від backend»
- «Сформуй звіт про помилки API»
- або якщо під час роботи з `getUnifiedTransactions` чи `analyzeTransactions` виникають помилки парсингу.

# Інструкції з виконання (Execution Steps)

Ти ЗОБОВ'ЯЗАНИЙ виконати такі кроки суворо за порядком, використовуючи скрипти (Node.js) для виконання запитів.

## Крок 1: Підготовка середовища та ключів

1. Завантаж змінну середовища `CPA_API_KEY` (із `.env` або `.env.local`).
2. Сформуй заголовки для запитів до закритих ендпоїнтів: `{"x-api-key": process.env.CPA_API_KEY}`[cite: 5].

## Крок 2: Виконання запитів (Data Fetching)

Виконай GET-запити до таких ендпоїнтів і збережи сирі відповіді:

1. **Джерело 1:** `https://cpa-server-vtel.onrender.com/api/finance1` (потребує `x-api-key`)[cite: 5].
2. **Джерело 2:** `https://cpa-server-vtel.onrender.com/api/finance2` (потребує `x-api-key`)[cite: 5].
3. **Курси валют:** `https://open.er-api.com/v6/latest/USD` (відкритий API, без ключа)[cite: 5].

## Крок 3: Аудит даних (Data Validation)

Перевір отримані дані на відповідність контрактам frontend:

**Для джерела 1:**

- Переконайся, що відповідь містить масив `transactions`[cite: 1].
- Перевір кожен елемент масиву: він має містити поля `type`, `amount` (число) та `currency` (рядок)[cite: 1].
- Зафіксуй транзакції, де сума (amount) <= 0[cite: 2].
- Познач валюти в нижньому регістрі (frontend очікує верхній регістр)[cite: 1].
- Зафіксуй статуси `type`, відмінні від "paid" (наприклад, "pending", "rejected")[cite: 1].

**Для джерела 2:**

- Переконайся, що відповідь — це плаский масив[cite: 1].
- Перевір формат кожного елемента: це має бути рядок, розділений пробілом (наприклад, `"300 usd"`)[cite: 1].
- Зафіксуй будь-які елементи, що не є рядками (вони позначаються як `"invalid"` на frontend)[cite: 1, 2].
- Переконайся, що сума успішно парситься як число (`parseFloat`)[cite: 1].

**Загальні перевірки курсів валют:**

- Зістав усі знайдені валюти (з обох джерел) з об'єктом курсів `rates`, отриманим від відкритого API[cite: 2, 5].
- Суворо зафіксуй будь-яку валюту, для якої немає курсу (це спричиняє помилку `Нет курса для ...` на frontend)[cite: 2].

## Крок 4: Формування звіту

На основі знайдених аномалій згенеруй звіт. Згрупуй проблеми за джерелами й типами помилок:

- Невалідний формат даних (очікувався інший тип).
- Проблеми із сумами (<= 0 або не парсяться).
- Невідомі валюти (відсутні у довіднику `rates`).
- Транзакції у статусі, відмінному від "paid" (для джерела 1)[cite: 2].

# Обмеження та правила (Constraints & Rules)

- **Лише читання:** заборонено виконувати запити, що змінюють дані.
- **Безпека ключів:** НІКОЛИ не виводь `CPA_API_KEY` у підсумковий звіт або логи.
- **Точність даних:** оперуй оригінальними значеннями з API. Frontend переводить суми в центи (`amount * 100`)[cite: 1], але у звіті вказуй початкові отримані значення.

# Формат виведення (Expected Output)

Надай користувачеві структурований звіт.

1. **Найменування та збереження файлів:**
   - Збережи результати у файл `docs/audits/api-audit-latest.md` (перезаписуючи його під час кожного нового аудиту).
   - Створи архівну копію з таймстемпом у форматі `docs/audits/api-audit-YYYY-MM-DD-HH-MM.md`.
   - Якщо користувач у промпті явно запросив PDF, напиши й виконай скрипт для конвертації звіту у формат PDF.
2. **Зведення:** дата перевірки, статус доступності всіх трьох ендпоїнтів.
3. **Джерело 1 (finance1):** список транзакцій із помилками структури, від'ємними/нульовими сумами й невідомими валютами.
4. **Джерело 2 (finance2):** список невалідних рядків і невідомих валют.
5. **Рекомендації:** технічні вказівки для backend у форматі `[Ендпоїнт] - [Проблема] -> [Очікувана поведінка]`.
6. Заверши відповідь суворо фразою: _«Аудит API завершено. Звіти сформовано. Чекаю подальших вказівок.»_
