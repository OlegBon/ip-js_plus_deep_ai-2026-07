# Архітектура проєкту «next-project»

Цей документ описує поточну архітектуру вебзастосунку, побудованого на Next.js.

## 1. Технологічний стек

- **Фреймворк:** [Next.js](https://nextjs.org/) (App Router)
- **Бібліотека UI:** [React](https://react.dev/)
- **Мова:** [TypeScript](https://www.typescriptlang.org/)
- **Стилізація:** [Tailwind CSS](https://tailwindcss.com/)
- **Лінтинг:** [ESLint](https://eslint.org/)
- **Середовище виконання скриптів:** [Node.js](https://nodejs.org/)

## 2. Структура директорій

### 2.1. Візуальна структура

```
/next-project
├── app/                    # Вихідні файли застосунку (App Router)
│   ├── data-sources/       # Сторінка «Джерела даних»
│   └── lib/                # Допоміжна бізнес-логіка
├── docs/                   # Проєктна документація
│   └── audits/             # Артефакти аудиту API
├── public/                 # Статичні асети (зображення, шрифти)
├── scripts/                # Автоматизовані скрипти
└── .gemini/                # Конфігурація та правила для AI-агента
    ├── rules/              # Деталізовані файли правил
    └── skills/             # Готові сценарії для AI
├── .gitignore              # Файл для виключення файлів із Git
├── next.config.ts          # Конфігурація Next.js
├── package.json            # Залежності та скрипти
├── postcss.config.mjs      # Конфігурація PostCSS
├── tailwind.config.js      # Конфігурація Tailwind CSS
├── tsconfig.json           # Конфігурація TypeScript
└── README.md               # Документація проєкту
```

### 2.2. Опис ключових директорій

Проєкт використовує стандартну для Next.js структуру з App Router.

- `next-project/`
  - `app/`: основна директорія для сторінок і компонентів застосунку.
    - `layout.tsx`: кореневий макет застосунку.
    - `page.tsx`: головна сторінка (роут `/`).
    - `data-sources/page.tsx`: сторінка для відображення результатів аудиту API (роут `/data-sources`).
    - `lib/`: модулі з повторно використовуваною бізнес-логікою.
      - `api.js`: функції для взаємодії із зовнішніми API.
      - `calculator.js`, `analyzer.js`: модулі для фінансових розрахунків та аналізу транзакцій.
      - `adapters.js`: адаптери для перетворення даних із різних джерел на єдиний формат.
      - `config.js`: конфігураційні константи.
  - `public/`: статичні файли (зображення, іконки).
  - `docs/`: проєктна документація.
    - `architecture.md`: цей файл.
    - `progress.md`: журнал виконаних завдань.
    - `audits/`: директорія для зберігання артефактів, згенерованих скриптами аудиту.
  - `scripts/`: автоматизовані скрипти для виконання фонових завдань (наприклад, аудиту API).
  - `.gemini/`: правила та налаштування для AI-агента.
    - `rules/`: набір правил, що визначають поведінку AI-агента в різних контекстах (глобальні, локальні, специфічні для інструментів).
    - `skills/`: готові високорівневі сценарії, які AI-агент може виконувати для розв'язання конкретних завдань (наприклад, `api-response-auditor`).

## 3. Потік даних і рендеринг

1.  **Рендеринг:** застосунок використовує переважно **серверні компоненти React (RSC)**. Це дає змогу безпечно отримувати дані на сервері (зокрема з доступом до файлової системи для читання звітів аудиту) та зменшити обсяг коду, що надсилається клієнту.
2.  **Отримання даних:**
    - **Головна сторінка (`/`)**: дані із зовнішніх API запитуються в реальному часі під час рендерингу сторінки на сервері.
    - **Сторінка джерел (`/data-sources`)**: дані не запитуються з API напряму. Натомість сторінка читає й відображає результати останнього аудиту з файлів у директорії `docs/audits/`. Це забезпечує консистентність даних і зменшує навантаження на зовнішні сервіси.
3.  **Стани UI:** керуються стандартними засобами Next.js і React (наприклад, `loading.tsx`, `error.tsx`, хуки `useState`/`useEffect` у клієнтських компонентах).

## 4. Автоматизація та аудит

У проєкті реалізовано механізм автоматичного аудиту фінансових API.

- **Ініціатор:** скрипт `scripts/audit-api.mjs`, що запускається командою `npm run audit:api`.
- **Процес:**
    1. Скрипт звертається до фінансових API, визначених у `app/lib/config.js`.
    2. Отримані дані адаптуються до єдиного формату за допомогою функцій із `app/lib/adapters.js`.
    3. Бізнес-логіка з `app/lib/analyzer.js` аналізує транзакції на аномалії та проблеми.
    4. За результатами аналізу генеруються два артефакти в директорії `docs/audits/`:
        - `api-audit-latest.md`: докладний Markdown-звіт для аналізу людиною.
        - `calculation-transactions.json`: структуровані дані (JSON) для відображення на сторінці `/data-sources`.

Цей підхід дає змогу відокремити процес збирання й аналізу даних від їх відображення, а також вести історію аудитів.

## 5. Стилізація

Стилізацію повністю побудовано на утилітарних класах **Tailwind CSS**. Глобальні стилі зведено до мінімуму. Повторно використовувані набори стилів інкапсулюються всередині UI-компонентів.
