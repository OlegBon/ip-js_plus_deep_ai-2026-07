# Архитектура Проекта "next-project"

Этот документ описывает текущую архитектуру веб-приложения, построенного на Next.js.

## 1. Технологический стек

- **Фреймворк:** [Next.js](https://nextjs.org/) (App Router)
- **Библиотека UI:** [React](https://react.dev/)
- **Язык:** [TypeScript](https://www.typescriptlang.org/)
- **Стилизация:** [Tailwind CSS](https://tailwindcss.com/)
- **Линтинг:** [ESLint](https://eslint.org/)
- **Среда выполнения скриптов:** [Node.js](https://nodejs.org/)

## 2. Структура директорий

### 2.1. Визуальная структура

```
/next-project
├── app/                    # Исходные файлы приложения (App Router)
│   ├── data-sources/       # Страница "Источники данных"
│   └── lib/                # Вспомогательная бизнес-логика
├── docs/                   # Проектная документация
│   └── audits/             # Артефакты аудита API
├── public/                 # Статические ассеты (изображения, шрифты)
├── scripts/                # Автоматизированные скрипты
└── .gemini/                # Конфигурация и правила для AI-агента
    ├── rules/              # Детализированные файлы правил
    └── skills/             # Готовые сценарии для AI
├── .gitignore              # Файл для исключения файлов из Git
├── next.config.ts          # Конфигурация Next.js
├── package.json            # Зависимости и скрипты
├── postcss.config.mjs      # Конфигурация PostCSS
├── tailwind.config.js      # Конфигурация Tailwind CSS
├── tsconfig.json           # Конфигурация TypeScript
└── README.md               # Документация по проекту
```

### 2.2. Описание ключевых директорий

Проект использует стандартную для Next.js структуру с App Router.

- `next-project/`
  - `app/`: Основная директория для страниц и компонентов приложения.
    - `layout.tsx`: Корневой макет приложения.
    - `page.tsx`: Главная страница (роут `/`).
    - `data-sources/page.tsx`: Страница для отображения результатов аудита API (роут `/data-sources`).
    - `lib/`: Модули с переиспользуемой бизнес-логикой.
      - `api.js`: Функции для взаимодействия с внешними API.
      - `calculator.js`, `analyzer.js`: Модули для финансовых расчетов и анализа транзакций.
      - `adapters.js`: Адаптеры для преобразования данных из разных источников в единый формат.
      - `config.js`: Конфигурационные константы.
  - `public/`: Статические файлы (изображения, иконки).
  - `docs/`: Проектная документация.
    - `architecture.md`: Этот файл.
    - `progress.md`: Журнал выполненных задач.
    - `audits/`: Директория для хранения артефактов, сгенерированных скриптами аудита.
  - `scripts/`: Автоматизированные скрипты для выполнения фоновых задач (например, аудит API).
  - `.gemini/`: Правила и настройки для AI-агента.
    - `rules/`: Набор правил, определяющих поведение AI-агента в различных контекстах (глобальные, локальные, специфичные для инструментов).
    - `skills/`: Готовые, высокоуровневые сценарии, которые AI-агент может выполнять для решения конкретных задач (например, `api-response-auditor`).

## 3. Поток данных и рендеринг

1.  **Рендеринг:** Приложение использует преимущественно **серверные компоненты React (RSC)**. Это позволяет безопасно получать данные на сервере (включая доступ к файловой системе для чтения отчетов аудита) и уменьшить объем кода, отправляемого на клиент.
2.  **Получение данных:**
    - **Главная страница (`/`)**: Данные из внешних API запрашиваются в реальном времени при рендеринге страницы на сервере.
    - **Страница источников (`/data-sources`)**: Данные не запрашиваются из API напрямую. Вместо этого страница читает и отображает результаты последнего аудита из файлов в директории `docs/audits/`. Это обеспечивает консистентность данных и снижает нагрузку на внешние сервисы.
3.  **Состояния UI:** Управляются стандартными средствами Next.js и React (например, `loading.tsx`, `error.tsx`, хуки `useState`/`useEffect` в клиентских компонентах).

## 4. Автоматизация и Аудит

В проекте реализован механизм автоматического аудита финансовых API.

- **Инициатор:** Скрипт `scripts/audit-api.mjs`, запускаемый командой `npm run audit:api`.
- **Процесс:**
    1. Скрипт обращается к финансовым API, определенным в `app/lib/config.js`.
    2. Полученные данные адаптируются к единому формату с помощью функций из `app/lib/adapters.js`.
    3. Бизнес-логика из `app/lib/analyzer.js` анализирует транзакции на предмет аномалий и проблем.
    4. По результатам анализа генерируются два артефакта в директории `docs/audits/`:
        - `api-audit-latest.md`: Детальный Markdown-отчет для анализа человеком.
        - `calculation-transactions.json`: Структурированные данные (JSON) для отображения на странице `/data-sources`.

Этот подход позволяет отделить процесс сбора и анализа данных от их отображения, а также вести историю аудитов.

## 5. Стилизация

Стилизация полностью построена на утилитарных классах **Tailwind CSS**. Глобальные стили сведены к минимуму. Переиспользуемые наборы стилей инкапсулируются внутри UI-компонентов.
