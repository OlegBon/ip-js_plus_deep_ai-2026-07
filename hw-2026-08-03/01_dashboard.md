# 📊 Personal Dashboard

Современный, модульный и масштабируемый веб-дашборд для агрегации личной и рабочей информации, управления рутинами и отслеживания метрик.

---

## 🛠 1. Технологический стек

Для реализации отзывчивого интерфейса с упором на компонентный подход и безопасность выбран следующий стек:

- **Фреймворк:** Next.js (App Router). Позволяет легко совместить SSR (для SEO и начальной загрузки) и клиентские компоненты для виджетов.
- **Стилизация:** Tailwind CSS + UI-библиотека (Shadcn UI). Обеспечивает быстрый перенос сложных Figma-дизайнов в pixel-perfect интерфейс.
- **База данных:** PostgreSQL (строгая типизация и надежность) + Prisma ORM.
- **Автоматизация и агрегация данных:** n8n или Make. Идеально для сбора новостей, парсинга курсов валют и проброса данных от ИИ, чтобы не перегружать основной бекенд приложения.

### Альтернативы для фоновых задач (вместо n8n / Make):

Для случаев, когда важна детерминированность данных и чистая архитектура в рамках монорепозитория:

1.  **Кастомные Node.js скрипты + Cron (Code-First подход):** Скрипты лежат в папке `scripts/` или `workers/`. Запускаются локальным cron, GitHub Actions или PM2. Дают жесткий контроль, но требуют самостоятельной реализации ретраев и логирования.
2.  **Платформы для фоновых задач (Trigger.dev, Inngest):** Код живет в Next.js, но выполняется на внешней инфраструктуре, обходя лимиты Vercel. Из коробки есть дашборд, ретраи и типизация.
3.  **BullMQ + Redis:** Классические очереди сообщений для тяжелых и масштабируемых бекендов. Максимальная надежность, но требует поддержки инфраструктуры (Redis, воркеры) - **<span style="color: red;">здесь точно будут излишне) Не тот объем продукта. ## 🖥 2. Структура страниц и UX/UI

- **Главный Дашборд (`/dashboard`):** Модульная сетка виджетов (grid layout). Используются модульные карточки с графиками и статистикой, а также боковая панель навигации (Sidebar) с мягкими тенями.
- **Страница авторизации (`/auth`):** Минималистичная форма входа по центру.
- **Трекер привычек/настроения:** Визуализация в виде "тепловой карты" (heat map), аналогично графику контрибуций GitHub.
- **Рутины и задачи (`/routines`):** Линейный список с чекбоксами, приоритетами и датами.

## 🔐 3. Авторизация и безопасность

Ориентация на удобство (Mobile First) и отказ от классических паролей:

- **Основной метод:** Passwordless авторизация (Magic Link на почту) + OAuth (Google/Apple).
- **Альтернативный метод:** Интеграция Telegram Bot API (вход через Telegram Web App/Login Widget).
- **Безопасность:** JWT-токены с коротким сроком жизни (access) и httpOnly куки (refresh). Финансовые и чувствительные данные не хранятся в открытом виде.

## 🧩 4. Спецификация виджетов

Каждый виджет разрабатывается как независимый React-компонент, управляющий своим состоянием загрузки (Skeleton) и ошибками (Error Boundary).

### Базовые виджеты

- **Дата и время:** Крупная типографика. Динамическая смена темы в зависимости от времени суток.
- **Погода:** Текущая, минимальная/максимальная температура за день. Анимированная векторная иконка. По умолчанию подтягивает локацию пользователя (например, Харьков), с возможностью изменения.
- **События календаря:** Вертикальный таймлайн на 24 часа. Интеграция через Google Calendar API (Read-only).
- **Чек-лист рутин (Daily Habits):** Список с круглыми чекбоксами, анимацией зачеркивания и Progress Bar (например, "Выпить 1л воды", "Покормить и погладить Карамельку").
- **Новостной фид (News & Trends):** Карусель или компактный список. Парсинг через NewsAPI или RSS (теги: `AI`, `n8n`, `Fullstack`, `Finance`). Ограничение: 5-7 топ-новостей за 12 часов. Если API новостей недоступно (таймаут 5 секунд), компонент должен отрендерить Fallback-UI с текстом 'Не удалось загрузить новости' и кнопкой 'Повторить'. При успешной загрузке данные кэшируются на 15 минут.

### Расширенные виджеты (Опционально)

- **AI Insights (Ассистент):** Ежедневная сводка от LLM (погода, задачи, новости, советы по продуктивности).
- **Pomodoro Таймер:** Круговой прогресс-бар с Web Push уведомлениями и интеграцией с Telegram-ботом.

## ⚙️ 5. Логика управления дашбордом

### Редактирование виджетов (Customization)

- **UX подход:** Боковая выезжающая панель (Drawer).
- **Функционал:** Список доступных виджетов с Toggle Switches. Мгновенное добавление/скрытие на сетке с плавной анимацией.
- **Хранение:** Layout config сохраняется в JSON-формате в базе данных для синхронизации между устройствами.

## 🗄 6. Архитектура базы данных

Используется PostgreSQL с `JSONB`-полями для гибкого хранения конфигураций.

```prisma
// model User: Базовая информация и авторизация
model User {
  id            String    @id @default(uuid())
  email         String?   @unique
  telegramId    String?   @unique
  name          String?
  createdAt     DateTime  @default(now())

  dashboard     DashboardConfig?
  routines      Routine[]
  aiInsights    AiInsight[]
}

// model DashboardConfig: Хранение состояния дашборда
model DashboardConfig {
  id          String   @id @default(uuid())
  userId      String   @unique
  user        User     @relation(fields: [userId], references: [id], onDelete: Cascade)

  // JSONB поле для хранения массива виджетов и их координат
  layout      Json     @default("[]")
  preferences Json     @default("{}")
  updatedAt   DateTime @updatedAt
}

// model Routine: Правила для генерации ежедневных чек-листов
model Routine {
  id          String   @id @default(uuid())
  userId      String
  user        User     @relation(fields: [userId], references: [id], onDelete: Cascade)

  title       String
  cronRule    String
  isActive    Boolean  @default(true)

  logs        RoutineLog[]
}

// model RoutineLog: Фиксация выполнения рутины в конкретный день
model RoutineLog {
  id          String   @id @default(uuid())
  routineId   String
  routine     Routine  @relation(fields: [routineId], references: [id], onDelete: Cascade)

  completedAt DateTime @default(now())
  date        String   // YYYY-MM-DD
}
```

## 🤖 7. Интеграция AI-ассистента

Пайплайн работы AI-ассистента для генерации персонализированных сводок:

1. **Сбор контекста:** Сервер собирает пакет данных (рутины, погода, новости, статистика).
2. **Оркестрация:** Данные отправляются через Webhook в сценарий автоматизации.
3. **Формирование промпта (LLM):** Формирование системного промпта на основе собранного контекста.
4. **Доставка:** Ответ возвращается в базу данных или пушится в Telegram-бот пользователя.

### Подходы к реализации AI-логики:

- **Vercel AI SDK (Внутри Next.js):** Идеально для работы со стримингом ответов и Server Actions прямо в коде приложения - **<span style="color: red;">нужно проверить, не платный ли он. Тут n8n будет лучше, если пойдешь по этому пути</span>**.
- **Внешняя оркестрация (n8n / Make):** Паттерн слабой связности. Снижает нагрузку на основной сервер Next.js и позволяет визуально менять цепочки промптов без передеплоя.
