# 📊 Personal Dashboard

Сучасний, модульний і масштабований вебдашборд для агрегації особистої та робочої інформації, керування рутинами й відстеження метрик.

---

## 🛠 1. Технологічний стек

Для реалізації чуйного інтерфейсу з упором на компонентний підхід і безпеку обрано такий стек:

- **Фреймворк:** Next.js (App Router). Дає змогу легко поєднати SSR (для SEO та початкового завантаження) і клієнтські компоненти для віджетів.
- **Стилізація:** Tailwind CSS + UI-бібліотека (Shadcn UI). Забезпечує швидке перенесення складних Figma-дизайнів у pixel-perfect інтерфейс.
- **База даних:** PostgreSQL (строга типізація та надійність) + Prisma ORM.
- **Автоматизація та агрегація даних:** n8n або Make. Ідеально для збирання новин, парсингу курсів валют і передавання даних від AI, щоб не перевантажувати основний backend застосунку.

### Альтернативи для фонових завдань (замість n8n / Make):

Для випадків, коли важливі детермінованість даних і чиста архітектура в межах монорепозиторію:

1.  **Кастомні Node.js-скрипти + Cron (Code-First підхід):** скрипти лежать у папці `scripts/` або `workers/`. Запускаються локальним cron, GitHub Actions або PM2. Дають жорсткий контроль, але потребують самостійної реалізації ретраїв і логування.
2.  **Платформи для фонових завдань (Trigger.dev, Inngest):** код живе в Next.js, але виконується на зовнішній інфраструктурі, оминаючи ліміти Vercel. З коробки є дашборд, ретраї та типізація.
3.  **BullMQ + Redis:** класичні черги повідомлень для важких і масштабованих backend. Максимальна надійність, але потребує підтримки інфраструктури (Redis, воркери) — **⚠️ тут точно буде зайвим) Не той обсяг продукту. Та й Make, мабуть, я б не рекомендував)**.

## 🖥 2. Структура сторінок і UX/UI

- **Головний дашборд (`/dashboard`):** модульна сітка віджетів (grid layout). Використовуються модульні картки з графіками й статистикою, а також бічна панель навігації (Sidebar) з м'якими тінями.
- **Сторінка авторизації (`/auth`):** мінімалістична форма входу по центру.
- **Трекер звичок/настрою:** візуалізація у вигляді «теплової карти» (heat map), аналогічно графіку контрибуцій GitHub.
- **Рутини й завдання (`/routines`):** лінійний список із чекбоксами, пріоритетами та датами.

---

## 🔐 3. Авторизація та безпека

Орієнтація на зручність (Mobile First) і відмова від класичних паролів:

- **Основний метод:** Passwordless-авторизація (Magic Link на пошту) + OAuth (Google/Apple).
- **Альтернативний метод:** інтеграція Telegram Bot API (вхід через Telegram Web App/Login Widget).
- **Безпека:** JWT-токени з коротким строком життя (access) та httpOnly cookie (refresh). Фінансові й чутливі дані не зберігаються у відкритому вигляді.

## 🧩 4. Специфікація віджетів

Кожен віджет розробляється як незалежний React-компонент, що керує власним станом завантаження (Skeleton) і помилками (Error Boundary).

### Базові віджети

- **Дата й час:** велика типографіка. Динамічна зміна теми залежно від часу доби.
- **Погода:** поточна, мінімальна/максимальна температура за день. Анімована векторна іконка. За замовчуванням підтягує локацію користувача (наприклад, Харків), з можливістю зміни.
- **Події календаря:** вертикальний таймлайн на 24 години. Інтеграція через Google Calendar API (Read-only).
- **Чекліст рутин (Daily Habits):** список із круглими чекбоксами, анімацією закреслення та Progress Bar (наприклад, «Випити 1 л води», «Погодувати й погладити Карамельку»).
- **Стрічка новин (News & Trends):** карусель або компактний список. Парсинг через NewsAPI або RSS (теги: `AI`, `n8n`, `Fullstack`, `Finance`). Обмеження: 5–7 топ-новин за 12 годин. Якщо API новин недоступне (таймаут 5 секунд), компонент має відрендерити Fallback-UI з текстом «Не вдалося завантажити новини» та кнопкою «Повторити». За успішного завантаження дані кешуються на 15 хвилин.

### Розширені віджети (опційно)

- **AI Insights (асистент):** щоденне зведення від LLM (погода, завдання, новини, поради щодо продуктивності).
- **Pomodoro-таймер:** круговий прогрес-бар із Web Push-сповіщеннями та інтеграцією з Telegram-ботом.

## ⚙️ 5. Логіка керування дашбордом

### Редагування віджетів (Customization)

- **UX-підхід:** бічна виїзна панель (Drawer).
- **Функціональність:** список доступних віджетів із Toggle Switches. Миттєве додавання/приховування на сітці з плавною анімацією.
- **Зберігання:** Layout config зберігається у JSON-форматі в базі даних для синхронізації між пристроями.

### Керування рутинними справами (Routine Builder) — **⚠️ так і не зрозумів, за яким принципом вони встановлюватимуться :)**

- **UX-підхід:** окрема сторінка `/settings/routines`.
- **Модель даних:** Cron-подібна логіка (щодня, за днями тижня, за датами).
- **Життєвий цикл:** щоденна генерація сервером «знімка» завдань на день (о 00:00).

## 🗄 6. Архітектура бази даних

Використовується PostgreSQL з `JSONB`-полями для гнучкого зберігання конфігурацій.

```prisma
// model User: Базовая информация и авторизация
model User {
  id            String    @id @default(uuid())
  email         String?   @unique
  telegramId    String?   @unique
  name          String?
  createdAt     DateTime  @default(now())

  dashboard     DashboardConfig?
  routines      Routine[]
  aiInsights    AiInsight[]
}

// model DashboardConfig: Хранение состояния дашборда
model DashboardConfig {
  id          String   @id @default(uuid())
  userId      String   @unique
  user        User     @relation(fields: [userId], references: [id], onDelete: Cascade)

  // JSONB поле для хранения массива виджетов и их координат
  layout      Json     @default("[]")
  preferences Json     @default("{}")
  updatedAt   DateTime @updatedAt
}

// model Routine: Правила для генерування щоденних чеклістів
model Routine {
  id          String   @id @default(uuid())
  userId      String
  user        User     @relation(fields: [userId], references: [id], onDelete: Cascade)

  title       String
  cronRule    String
  isActive    Boolean  @default(true)

  logs        RoutineLog[]
}

// model RoutineLog: Фіксація виконання рутини у конкретний день
model RoutineLog {
  id          String   @id @default(uuid())
  routineId   String
  routine     Routine  @relation(fields: [routineId], references: [id], onDelete: Cascade)

  completedAt DateTime @default(now())
  date        String   // YYYY-MM-DD
}
```

## 🤖 7. Інтеграція AI-асистента

Пайплайн роботи AI-асистента для генерації персоналізованих зведень:

1. **Збирання контексту:** сервер збирає пакет даних (рутини, погода, новини, статистика).
2. **Оркестрація:** дані надсилаються через Webhook до сценарію автоматизації.
3. **Формування промпту (LLM):** формування системного промпту на основі зібраного контексту.
4. **Доставлення:** відповідь повертається до бази даних або пушиться в Telegram-бот користувача.

### Підходи до реалізації AI-логіки:

- **Vercel AI SDK (усередині Next.js):** ідеально для роботи зі стримінгом відповідей і Server Actions просто в коді застосунку — **⚠️ потрібно перевірити, чи не платний він. Тут n8n буде кращим, якщо підеш цим шляхом**.
- **Зовнішня оркестрація (n8n / Make):** патерн слабкої зв'язності. Знижує навантаження на основний сервер Next.js і дає змогу візуально змінювати ланцюжки промптів без передеплою.
