# ⚙️ SaaS File Converter & API Platform

Мікросервіс для швидкої конвертації файлів із наданням публічного API для розробників. Проєкт поєднує зручний користувацький інтерфейс і надійну серверну інфраструктуру обробки даних.

---

## 🛠 1. Технологічний стек

Для реалізації сервісу, де важливі швидкість обробки файлів і надання API, обрано такий стек:

- **Фреймворк:** Next.js (App Router) — виступає як для рендерингу сторінок, так і для створення API-маршрутів.
- **Стилізація:** Tailwind CSS + Shadcn UI. Інтерфейс має бути pixel-perfect, реалізований строго за Figma-макетами з фокусом на мікроанімації Drag & Drop — **⚠️ найімовірніше, такого не буде)**.
- **База даних:** PostgreSQL + Prisma ORM (зберігання користувачів, API-ключів, логів конвертацій).
- **Сховище файлів:** S3-сумісне об'єктне сховище (AWS S3, Cloudflare R2 або MinIO). Архітектуру варто одразу закладати з прицілом на масштабування — щоб зі зростанням бази можна було легко перевести користувачів на просунуті тарифи, пропонуючи виділені пули, аж до 5 TB дискового простору під архіви.
- **Рушії конвертації (Core):**
  - _Зображення:_ бібліотека `sharp` (Node.js) — неймовірно швидка конвертація без зовнішніх залежностей.
  - _Документи:_ використання зовнішнього мікросервісу (наприклад, Gotenberg на базі Docker) для надійної конвертації DOCX у PDF.

## 📁 2. Формати файлів і базова функціональність

Для MVP (Minimum Viable Product) обрано два найбільш затребувані напрями. Як тестовий прогін чудово підійде завантаження умовного файла `karamelka_photo.jpg` або робочого регламенту в `.docx`.

1.  **Зображення (JPG ↔ PNG):** легковага операція. Виконується синхронно прямо на сервері Next.js.
2.  **Документи (DOCX → PDF):** важча операція. Потребує ізоляції, щоб не заблокувати Event Loop основного сервера — **⚠️ гарне зауваження!!!**.

## 🖥 3. Структура сторінок і UX/UI

- **Головна сторінка (`/`):**
  - Hero-блок із коротким описом цінності сервісу.
  - Два масивні Drag & Drop-віджети: «Зображення (JPG у PNG)» і «Документи (DOCX у PDF)».
  - Анімація завантаження (Progress bar) і кнопка «Завантажити результат» після успішної конвертації.
- **Особистий кабінет (`/dashboard`):**
  - блок керування профілем (зміна імені/email);
  - **секція API:** генерація, копіювання та відкликання (revoke) унікального API-ключа;
  - **налаштування сховища:** Toggle-перемикач «Зберігати результати конвертації»;
  - **файловий менеджер:** таблиця зі списком раніше сконвертованих файлів (ім'я, дата, розмір, кнопка «Завантажити»).
- **Документація API (`/docs`):**
  - статична сторінка з описом ендпоїнтів, прикладами запитів (cURL, JS) і списком можливих кодів помилок.

## 🛡 4. Обробка непередбачених ситуацій (Edge Cases)

Сервіс, що працює з файлами користувачів, має бути максимально захищеним від падінь:

- **Перевищення розміру:** суворе обмеження (наприклад, 5 MB для безкоштовного тарифу). Валідація відбувається спочатку на клієнті, потім жорстко перевіряється на сервері. У разі перевищення виводиться Toast-сповіщення.
- **Неправильний формат (MIME-type spoofing):** перевірка не лише за розширенням (умовний `.jpg`), а за реальним MIME-типом файла на сервері. Якщо завантажено `.exe`, перейменований на `.jpg`, сервер віддає статус `415 Unsupported Media Type`.
- **Таймаут або помилка конвертації:** якщо рушій не впорався з пошкодженим файлом, сервер перехоплює виняток і повертає зрозумілу помилку: «Файл пошкоджено або він має неправильну структуру» (статус `422 Unprocessable Entity`).

## 🔐 5. Авторизація та безпека

- **Основний метод:** NextAuth.js (Email + Password) або OAuth (Google/GitHub).
- **Резервний метод (Telegram):** у разі втрати пароля користувач запитує відновлення через Telegram-бота, отримуючи безпечний Magic Link для скидання.

## ⚙️ 6. Механізм роботи публічного API

API — це ядро цього продукту. Воно має бути передбачуваним і безпечним.

- **Ендпоїнт:** `POST /api/v1/convert`
- **Автентифікація запитів:** ключ передається в заголовку `Authorization: Bearer <API_KEY>`. Без ключа або з невалідним ключем сервер миттєво віддає `401 Unauthorized`.
- **Rate Limiting:** захист від DDoS і зловживань. Наприклад, не більш як 10 конвертацій за хвилину для одного ключа (повертається статус `429 Too Many Requests`).
- **Payload (тіло запиту):** формат `multipart/form-data`, що містить вихідний файл і параметр `targetFormat`.
- **Response (відповідь):** у разі успіху повертається JSON із посиланням на завантаження (що спливає через 1 годину, якщо користувач вимкнув збереження файлів) або сам файл як потік (Stream/Buffer).

## 🎨 7. Візуальні референси

- **Головна сторінка:** мінімалізм у стилі ILovePDF, Vercel або Stripe. Акцент на зоні завантаження файла (пунктирна рамка, що змінює колір під час наведення файла).
- **Особистий кабінет та API Docs:** строгий технічний дизайн (як у Tailwind UI або Stripe Docs) із темною бічною панеллю, блоками коду з підсвічуванням синтаксису та чіткими таблицями даних.
