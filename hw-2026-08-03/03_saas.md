# ⚙️ SaaS File Converter & API Platform

Микро-сервис для быстрой конвертации файлов с предоставлением публичного API для разработчиков. Проект объединяет удобный пользовательский интерфейс и надежную серверную инфраструктуру обработки данных.

---

## 🛠 1. Технологический стек

Для реализации сервиса, где важна скорость обработки файлов и раздача API, выбран следующий стек:

- **Фреймворк:** Next.js (App Router) — выступает как для рендеринга страниц, так и для создания API-маршрутов.
- **Стилизация:** Tailwind CSS + Shadcn UI. Интерфейс должен быть pixel-perfect, реализован строго по Figma-макетам с фокусом на микроанимации Drag & Drop.
- **База данных:** PostgreSQL + Prisma ORM (хранение пользователей, API-ключей, логов конвертаций).
- **Хранилище файлов:** S3-совместимое объектное хранилище (AWS S3, Cloudflare R2 или MinIO). Архитектуру стоит сразу закладывать с прицелом на масштабирование — чтобы при росте базы можно было легко перевести пользователей на продвинутые тарифы, предлагая выделенные пулы, вплоть до 5 TB дискового пространства под архивы.
- **Движки конвертации (Core):**
  - _Изображения:_ Библиотека `sharp` (Node.js) — невероятно быстрая конвертация без внешних зависимостей.
  - _Документы:_ Использование внешнего микросервиса (например, Gotenberg на базе Docker) для надежной конвертации DOCX в PDF.

---

## 📁 2. Форматы файлов и базовый функционал

Для MVP (Minimum Viable Product) выбраны два самых востребованных направления. В качестве тестового прогона отлично подойдет загрузка условного файла `karamelka_photo.jpg` или рабочего регламента в `.docx`.

1.  **Изображения (JPG ↔ PNG):** Легковесная операция. Выполняется синхронно прямо на сервере Next.js.
2.  **Документы (DOCX → PDF):** Более тяжелая операция. Требует изоляции, чтобы не заблокировать Event Loop основного сервера.

## 🖥 3. Структура страниц и UX/UI

- **Главная страница (`/`):**
  - Hero-блок с кратким описанием ценности сервиса.
  - Два массивных виджета Drag & Drop: "Изображения (JPG в PNG)" и "Документы (DOCX в PDF)".
  - Анимация загрузки (Progress bar) и кнопка "Скачать результат" после успешной конвертации.
- **Личный кабинет (`/dashboard`):**
  - Блок управления профилем (изменение имени/email).
  - **Секция API:** Генерация, копирование и отзыв (revoke) уникального API-ключа.
  - **Настройки хранилища:** Toggle-переключатель "Сохранять результаты конвертации".
  - **Файловый менеджер:** Таблица со списком ранее сконвертированных файлов (Имя, Дата, Размер, кнопка "Скачать").
- **Документация API (`/docs`):**
  - Статическая страница с описанием эндпоинтов, примерами запросов (cURL, JS) и списком возможных кодов ошибок.

## 🛡 4. Обработка непредвиденных ситуаций (Edge Cases)

Сервис, работающий с пользовательскими файлами, должен быть максимально защищен от падений:

- **Превышение размера:** Строгое ограничение (например, 5 MB для бесплатного тарифа). Валидация происходит сначала на клиенте, затем жестко проверяется на сервере. При превышении выводится Toast-уведомление.
- **Неверный формат (MIME-type spoofing):** Проверка не просто по расширению (условный `.jpg`), а по реальному MIME-типу файла на сервере. Если загружен `.exe`, переименованный в `.jpg`, сервер отдает статус `415 Unsupported Media Type`.
- **Таймаут или ошибка конвертации:** Если движок не справился с битым файлом, сервер перехватывает исключение и возвращает понятную ошибку: "Файл поврежден или имеет неверную структуру" (Статус `422 Unprocessable Entity`).

## 🔐 5. Авторизация и безопасность

- **Основной метод:** NextAuth.js (Email + Password) или OAuth (Google/GitHub).
- **Резервный метод (Telegram):** При утере пароля пользователь запрашивает восстановление через Telegram-бота, получая безопасную Magic Link для сброса.

---

## ⚙️ 6. Механизм работы публичного API

API — это ядро данного продукта. Оно должно быть предсказуемым и безопасным.

- **Эндпоинт:** `POST /api/v1/convert`
- **Аутентификация запросов:** Ключ передается в заголовке `Authorization: Bearer <API_KEY>`. Без ключа или с невалидным ключом сервер мгновенно отдает `401 Unauthorized`.
- **Rate Limiting:** Защита от DDoS и злоупотреблений. Например, не более 10 конвертаций в минуту для одного ключа (возвращается статус `429 Too Many Requests`).
- **Payload (Тело запроса):** Формат `multipart/form-data`, содержащий исходный файл и параметр `targetFormat`.
- **Response (Ответ):** При успехе возвращается JSON со ссылкой на скачивание (истекающей через 1 час, если пользователь отключил сохранение файлов) или сам файл в виде потока (Stream/Buffer).

## 🎨 7. Визуальные референсы

- **Главная страница:** Минимализм в стиле ILovePDF, Vercel или Stripe. Акцент на зоне загрузки файла (пунктирная рамка, меняющая цвет при наведении файла).
